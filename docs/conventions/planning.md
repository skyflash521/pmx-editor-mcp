# 計画書の規約

実装計画書へ書かないものと、**その修正を認める場合の閉じた一覧**、**不適合をレビューでどう扱うか**の
正本。

対象は実装計画書——実装の着手前に手順を確定し、実装が済めば削除される一時ドキュメント——とする。
進捗・引き継ぎを記録する文書は対象外。

計画書へ足した記述は、レビューを一度余計に掛けたうえで捨てることになる。**書くほど工数が増え、
残る成果は増えない。**

## 1. 正本に属する設計を書かない

**確定した設計——設計値・規則・表・手順——を計画書へ書かない。** 決まった時点で正本へ直接書く
(その正本がまだ無ければ作る)。**正本がコードである設計**——内部の分割・命名・制御の流れ・
アルゴリズム——は、文書を作らず実装で確定させる。

## 2. 書いてよい記述

計画書は、次の一手を設計判断なしに着手できる状態にするための文書とする。置いてよいのは、
**その計画で何を実装するかの一文・着手順とステップの区切り・各ステップの完了条件(テストの方針を
含む)・前提とその裏取り・未検証として残る事項・仕様書とコードの食い違いとその処置**である。それ以外は
**過剰**とし、置かない。判定の母集団は、差分が計画書へ追加・変更する記述の全件とする。過剰の類型を
挙げる。

- **正本へ属する記述。** **移した記述の代わりに道しるべを残さない**——読み手は正本を読む。上の
  許可項目の中で正本を名指しすることは別である。
- **既にある記述の言い直し。** 同じ内容の要約・再掲・節をまたぐ重複、語句だけを整えた書き換え。
- **規則・検査の必要性を説く理由づけ。** 「これを課さないと〜してしまう」の類は、その規則を
  持つ正本へ書く。計画書には結論だけ置く。
- **着手の判断に要らない背景。** 経緯、検討して採らなかった案、案どうしの比較の記録。
- **実装すればコードが正本になる細部。** 内部の分割・命名・制御の流れなど。**正本を持つ設計値**
  ——フラグ名・終了コード・モジュール配置・エラーのコードなど、規約か仕様書が持つもの——は
  これに当たらない。確定させたうえで、その正本へ書く。
- **既に実装した範囲の記述。** 済んだ手順は計画書から消える側で、書き直す対象ではない。
- **この計画で実装しない範囲の記述。** 将来の構想、次の計画へ回す事柄。

## 3. 修正は原則禁止とし、認める形を限る

**計画書を作成したコミットより後の変更はすべて修正とし、原則として行わない。** 認めるのは下記の
W1〜W5だけで、**この一覧は閉じている**。どれにも当てはまらない修正は、内容の当否を問わず却下する
——正確になること・詳しくなること・読みやすくなることは、消える文書では認める理由にならない。

**修正の既定の形は削除である。** 挿入——行の追加、および既存の行の書き換えのうち削除だけでは
成立しない部分——を含んでよいのはW3〜W5に限り、**W1・W2は挿入をひとつも含まない**。次の2つは挿入に
当たらない——**語を1つも足さない折り返しの調整**(削除で残った行を桁幅へ折り直すだけのもの)と、
**既存の名指しの付け替え**(参照先の差し替え)。**語の追加・語順の変更・接続語の補いは挿入とする。**

判定は**挿入ブロックごと**に行う。挿入ブロックとは、**連続する挿入のかたまりと、それが置き換えた
文・段落**を指す(差分ツールのハンクの区切りは文脈行数の指定で動くので、単位に使わない)。
**コミットやファイルの行数が純減していることは適合の根拠にならない**(純減の中の挿入も全件が
判定対象である)。挿入ブロックごとに、**それがW3・W4・W5のどれに当たるか**を言えなければならず、
言えなければ却下する。
判定は修正の動機ではなく差分で行い、レビュー指摘への対応としてなされた修正も同じく判定する。

認める修正は次のとおり。

- **W1 削る。** 記述の削除、および計画書そのものの削除。挿入を含まない。
- **W2 正本へ移す。** 計画書の記述を正本へ移し、計画書側は消す。**計画書側は削除だけで完結させる**
  ——移送先を指す道しるべ・移した内容の要約・残った文の言い換えや接続の調整は、どれもW2に含まない。
  削除で前後の文意が通らなくなる場合は、通るように直すのではなく**その文・その段落ごと消す**。
  **他の計画書がその記述を名指ししていたら、移送先の正本への名指しへ付け替えるところまでを含む。**
- **W3 前提と裏取りを直す。** **対象は、前提と裏取りの記述、および未確定の設計判断(推奨・選択肢・
  「実装時に判断」が残っているもの)を含む記述に限る。** 他の記述を「前提の書き改め」と称して直す
  ことはできない。認めるのは、未確定を確定させる修正と、前提の裏取りを直す修正——未検証のまま
  残っていた前提を裏取りする、観測が誤っていたと分かった前提を書き改める。挿入は**当該箇所の置換に
  限り、置換後の行数が置換前を超えない**。**例外は裏取りの記録**で、出典・確かめた結果・出典と
  一致したかを書き足すぶんは行数の条件を課さない。確定させた設計の中身は正本へ書き、計画書へは
  残さない。
- **W4 着手を妨げる誤りを直す。** **これから着手する手順**が、書かれたとおりに実行すると**必ず
  止まる**場合に限る。当たるのは次のD1〜D4だけで、**この一覧は閉じている**。
  - **D1 名指しの先が実在しない。** ファイル・コマンド・引数・正本の節・ステップ番号・識別子が
    存在しない、または改名されている。
  - **D2 正本と矛盾する。** 手順が正本の定めと食い違っていて、どちらに従うか決められない。
  - **D3 順序が成立しない。** 後のステップの成果を前のステップが前提にしている等、その順では
    実行できない。
  - **D4 完了条件を判定できない。** 判定の対象が存在しない、または条件が相互に矛盾している。

  **主張する側は、その手順を書かれたとおりに実行したときの止まる箇所と止まり方を一文で言えなければ
  ならず、言えなければ却下する。** 曖昧・不足・抽象的であることは上の4つに当たらない——**書いて
  いないことは誤りではない**。足りないと感じた設計は、その場で確定させて正本へ書く(計画書へは
  書かない)。挿入は**誤っている語句の置換に限り、置換後の行数が置換前を超えず、文や段落の書き直しに
  ならないこと**。**消しても着手できるならW1で消す**——W4は消すと着手できなくなる場合に限る。
  実装済みの範囲との食い違いは、そろえるのではなくW1で消す。
- **W5 ステップの構成を変える。** 要件・設計が変わり、ステップの追加・削除・差し替え・順序変更が
  要る場合。**変わった設計が正本の差分として存在することを示せなければ却下する**(「要件が変わった」
  という申告だけでは足りない)。**増やしてよいのはステップの見出しと完了条件の行だけ**で、既存
  ステップの本文への加筆は含まない。変わった設計の中身は正本へ書く(W2)。

**過剰**とした記述は、**修正の動機が上のどれであっても挿入できない**。**W1・W2の作業に伴って
生じたものも同じ**——移送や削除は、これらを足さずに完結できる(削除で残った文の整え直しと、移した
記述の代わりに置く道しるべが典型である)。加えて、**着手できる手順をさらに着手しやすくする更新**
——具体化・既存ステップ本文の細分化・例示や補足の追加・言い換えによる厳密化・「念のため」の
但し書き——は、W4ではなく不適合とする(W5が認めるステップの追加・差し替えはこれに当たらない)。

## 4. 不適合の扱い

**この規約に反する記述、またはこの規約が認めない修正**が差分にあれば、不適合とし、レビューの
指摘対象とする(収束を妨げる)。解消は**元へ戻す**か**削除**か**正本への移送**のいずれかで、
計画書の中で書き足しても書き直しても解消しない。

逆に、**解消が計画書への書き足しになる指摘は、この規約が挿入を認める場合だけ受け入れる。**
それ以外は反証するか、正本の側の修正として立て直す。
