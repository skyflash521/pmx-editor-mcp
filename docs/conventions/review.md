# レビュー規約

## 検査を迂回しない

検査が落ちる・通らない・時間が掛かるとき、直すのは製品の側(コード・定義・データ)か、検査自体の
誤りである。それ以外の手で、検査を通す、または通ったことにする行為(迂回)をしない。迂回は次の
とおりとする。

- 検査の項目・段・ケース・断定の削除。
- 検査を別の層・別の検査へ付け替えること。受入シナリオの段を単体テストへ移すことを含む。
- 期待値・許容・上限秒数・件数の上限の緩和。比べる項目の絞り込みを含む。
- 検査の飛ばし・無効化・除外。飛ばしの属性、除外の一覧、条件つきの飛ばしを含む。
- 検査を行う仕組み(照合、走らせる仕組み、検査の入力を作る定義)への、例外・免除・フラグ・特別扱いの追加。
- 検査が読む定義や製品の宣言(スキーマ・列挙・必須の別)の変更で、検査の入力を落とすこと、または
  検査が失敗する場面を無くすこと。
- 通すべき検査を通さずに確定させること。一部の検査だけを選んで通すことと、落ちた検査を原因を
  確かめずに再実行して通すことを含む。

迂回かどうかは目的で判定する。上のどれかに当たる変更が、検査を通す、または通ったことにする
効果を持つなら、理由が何であっても迂回とする。

## 迂回に当たらない変更

次の変更は迂回に当たらない。

- 検査が守る対象が製品から無くなったことによる、その検査の削除。
- 検査自体の誤りの修正。誤りを導出で示し、変えるのは誤っている項目だけとする。
- 製品の宣言の誤りの修正。宣言が実装の実際の振る舞いと食い違っていることと、その実際の振る舞いが
  製品の要求を満たすことを、差分で示してある。

## レビューでの判定

- 迂回に当たる差分と、迂回に当たらないことが読み取れない差分は、直す必要がある指摘として置く。
- 迂回であることを認めたうえで、同じ失敗を別の検査が捉えていること・対象範囲の外であること・
  既存の検査が同じ形であること・受容を理由に、この指摘を却下しない。迂回に当たらないことが
  事実で示されたときの反証は、この限りでない。指摘の成立と決着と件数の扱いは、レビュー応答の
  規約に従う。
