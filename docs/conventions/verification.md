# 検証手順

変更を確定させる前に通す検査の走らせ方と、検査の組み方を定める。
**どの検査が在るかはこの文書では定めない**——[check-set.ps1](../../scripts/check-set.ps1) と
[live-checks.ps1](../../scripts/live-checks.ps1) が持つ。

## 常設の検査

```
pwsh -File scripts/verify.ps1
```

これ1本で、**変えたものの群が走る**。どの道がどの群に当たるかは
[check-set.ps1](../../scripts/check-set.ps1) が決め、**表に当たらない道が1つでもあれば全件へ倒れる**。
`-All` を渡すと、変えたものに関わらず全件を走らせる。**落ちた検査も走らせていない検査も無ければ
終了コード0**、あれば1で、その名前を並べる(要る出来上がりが揃わなかった検査は走らせない)。

**通すのは変更を確定させる前の1回**とする——走る群は作業木にある変えたものから決まるので、
確定させた後に走らせても、変えたものが無く走る検査も無い。

## 実機に触る検査

**エディタかMCPクライアントに触る変更のときに通す。** 実機のエディタを起こして操作するので、
常設の検査とは分けて走らせる。

```
pwsh -File scripts/verify-live.ps1
```

参照クライアントの実機動作確認は、作業木の変更が文書だけの実行では走らない——この検査が見て
いるのはブリッジが載せるツール定義の綴りをクライアントが解けるかで、文書を変えても答えが
変わらない。変更が無い実行では走る。`-All` を渡すと、変えたものに関わらず全件を走らせる。

能力対応表の行だけを直したときは、直した行の検査に絞って走らせられる。突き合わせる版を指すと、
その版から中身の変わった行の検査だけが実機へ向かう。**変更を確定させる前の1回は、絞らずに上の
1本を通す**——絞った実行が見るのは、指した版との差だけである。

自分のツールを持たない能力対応表の行(ほかのツールへ埋め込まれる行・イベントの分岐の行・
受け手へ至る経路の行)は、ほかのツールの検査に覆われる。絞った実行はその覆いを引けないので、変わった行にそれが
あれば、行の名前を挙げて落ちる。そのときは絞らずに走らせる。

```
pwsh -File scripts/live-tools.ps1 -Since HEAD
```

## 不合格時の対応

- 不合格のまま変更を確定させない。修正が恒久文書の定める設計値に影響するときは、その設計値を
  決め直して恒久文書へ反映してから再実行する。
- **例外は、実装より先にテストだけを確定させる回とする。** その回は、足したテストが落ちたまま確定して
  よい。落ちてよいのはその回に足したテストに限り、ほかの検査は合格させる。**実装を入れる回で、その
  テストも合格させる。**
- 配布パッケージの生成が、第三者ライセンス表示の標準の本文を読めない旨で落ちた場合: 依存が増えて
  新しいライセンスが入っている。その本文をSPDXライセンスリストから
  `catalog/observed/licenses/<SPDXの綴り>.txt` へ転記してから再実行する。**組み立ては外部へ問い
  合わせない**ので、本文は追跡下に無いと使えない。
- 実機に触る検査の不合格: ホストのログを読んで原因を掴む。ログの所在は
  [操作役のスクリプト](../../scripts/host-control.ps1)の `status` が表示する。
- 受入シナリオか参照クライアントの実機動作確認で、画像が大きすぎて通らなかった場合: 送り出す
  画像の長辺の上限を下げる。**画像を応答から外す形へは改めない**——画像が得られることは
  [要求](../specs/requirements.md)が掲げる作業の成功の条件で、外せば作業そのものが成り立たない。
  最小まで下げても通らないなら、通らない理由を掴むところからやり直す。

## 検査の組み方

- **自動化できない確認は、この文書へ置かない。** 確かめられない範囲として仕様書へ記す——手順と
  して書くと、検査していないものを検査済みに見せることになる。
- **検査からだけ使う入口を、ビルド構成で分けない。** 配布物へ入れたうえで既定は閉じておき、開く
  条件を実行時に置く。構成で分けると、配布するものと検査したものが別物になる。
- **足した検査が落ちることを確かめる。** その変更だけを一度外し、検査が落ちてから戻す。外すのは
  自分が入れたものに限る——始めた時点から在った変更は触らない。落ちない検査は無い方がよい。
- **相手がどう読むかを見る検査を、自前の形状判定で代用しない。** 判定の基準を取り違えれば検査にも
  同じ穴が空く。実際に読む相手を通して確かめる。
- **入力から導ける値を、追跡下のデータとして置かない。** 要るときにその場で導く。**例外は、
  生成元と取り直し方が追跡下にあって、その場で導いた値との一致を常設の検査が見ること**と、
  **その差分からしか分からない不具合があること**の両方を満たすときだけとする。
