# バージョン付け

配布のバージョンの付け方を定める。

## バージョン番号の定義

配布のバージョンは [Directory.Build.props](../../Directory.Build.props) の `Version` だけが持つ。
ほかの場所へバージョンの番号を綴らない。

形は `MAJOR.MINOR.PATCH` とする。

## 互換を保つ範囲

互換性の無い変更とは、次のどれかについて、前のバージョンで動いていた使い方を動かなくする変更である。

| 対象 | 動かなくなる例 |
|---|---|
| 導入 | 配布物の名前・配置先・登録の仕方が変わり、[インストール指示書](../package/INSTALL.md)の更新の手順だけでは移れない |
| 対象のPMXエディタ | 下限のバージョンを上げる |

## どの桁を上げるか

リリースのたびに、前のリリースから入った変更のうち最も重いものに合わせて1つの桁を上げ、それより
下の桁を0に戻す。

### 0.x(安定前)

| 桁 | 上げる変更 |
|---|---|
| PATCH | 修正・内部の変更。0.0.x のあいだは、機能の追加・変更も互換性の無い変更もここへ入れてよい |
| MINOR | 機能の追加・変更。互換性の無い変更もここへ入れる |
| MAJOR | 上げない |

`0.0.x` から `0.1.0` へは、機能の追加・変更でMINORを上げる運用を始めると決めたときに移る。`0.y.z` から
`1.0.0` へは、以後は[互換を保つ範囲](#互換を保つ範囲)の互換を守ると決めたときに移る。どちらも個々の変更では移らない。

### 1.0.0 以降

| 桁 | 上げる変更 |
|---|---|
| PATCH | 修正・内部の変更 |
| MINOR | 互換を保つ機能の追加・変更 |
| MAJOR | 互換性の無い変更 |

## タグ

1回のリリースに、`git tag -a` で作るタグ `v<MAJOR.MINOR.PATCH>` を1つ打つ。打つ先は main のコミットで、
その時点の `Version` と同じ番号にする。
