# 実装計画書05: 配布・導入整備

pmx-editor-mcp を利用者へ配布できる形に整備する。配布パッケージの生成を1コマンド化する。

## 前提と裏取り

1. **配布対象の成果物**
   - 出典: [アーキテクチャ仕様書](../specs/pmx-editor-mcp-architecture.md)のプロジェクト構成(ホスト:
     `src/HostPlugin/PmxEditorMcp.HostPlugin.csproj`、成果物名 `PmxEditorMcp.dll`、
     net48・AnyCPU。ブリッジ: `src/Bridge/PmxEditorMcp.Bridge.csproj`、
     net10.0コンソール、成果物名 `PmxEditorMcp.Bridge.exe`)
   - 確かめた結果: ホストもブリッジも仕様書で成果物名・フレームワークが確定済み。
     [能力台帳](../specs/pmx-editor-mcp-capability-ledger.md)の実機確認は検証専用DLLと
     ハンドロールのブリッジによる**経路方式の成立**
     (DLLの `_plugin` 配置・パイプ・`claude mcp add` 経由の応答)の根拠であり、最終成果物
     どうしの成立は、ホストとブリッジは[検証手順書](../conventions/verification.md)の
     実機動作確認、ツールは実装計画書04の
     完了条件(実機確認)と本計画ステップ4の実測が担う。本計画はその2成果物を配布形に包む。
2. **再配布しない物**
   - 出典: アーキテクチャ仕様書の PEPlugin.dll の参照(利用規約が配布物のパッケージ内データの
     再配布を禁じているため、各自の導入物を参照するだけにする)
   - 確かめた結果: PEPlugin.dll・PMXエディタ本体は再配布禁止のため配布物へ含めない方針が
     同仕様書で確定している。ホストDLLはPEPlugin.dllを参照するのみで同梱しない
     (エディタが実行時に解決する)。
3. **導入側の前提環境**
   - 出典: READMEの開発環境と、.NET Framework 4.8 がWindows 10
     (バージョン1903以降)・Windows 11 にOSコンポーネントとして含まれるというOS仕様
   - 確かめた結果: Windows x64・PMXエディタ(x64版)・Claude Code CLI。ブリッジ
     (net10.0)は自己完結型(self-contained)で発行するため .NET ランタイムの追加導入は
     不要。ホストDLL(net48)は .NET Framework 4.8 を要するが、上記OSにはOS同梱であり
     追加導入不要——能力台帳の実機確認でも、追加導入なしの本開発機(Windows 11)で
     net48プラグインDLLがエディタから実行できている。利用者向け前提には対応OS
     (Windows 10 バージョン1903以降/Windows 11)を明記する。
4. **ブリッジの自己完結型・単一ファイル発行**
   - 出典: 一般の .NET SDK 機能(win-x64 向け self-contained + PublishSingleFile)
   - 確かめた結果: 本リポジトリのブリッジ構成(net10.0+ModelContextProtocol 2.2.0)での
     発行成立は**未検証**である。実装ステップ1で発行と起動・MCP応答を実測し、成立を
     確認してからパッケージ生成に組み込む。成立しない場合(単一ファイル化と依存の
     非互換等)は、フレームワーク依存発行へ切り替える。切り替えるときは、導入手順への .NET
     ランタイムの前提の追加に加えて、内容物の記述・同梱ランタイムのライセンス転記・
     `package.ps1` の発行手順・利用者向け前提の4箇所もあわせて書き換える。

## 確定する設計値

### 配布と導入の整備で確かめること

- 検証手順書の検査一覧へ「パッケージ生成: `pwsh scripts/package.ps1` / 合格条件: スクリプトが成功し
  内容物検査を通過」を追記する。
- README(リポジトリ直下)には概要と `README.txt` テンプレートへのリンクを追記する(READMEの本文は
  最小限を維持する)。

## 実装ステップ

1. ブリッジの自己完結型・単一ファイル発行を実測する(上記の発行プロパティ4点を明示した
   発行コマンドの成立と、**発行されたexeを空の一時ディレクトリへ単独コピーして**の起動・
   MCPクライアントからの接続確立・`ping` ツールの応答——発行ディレクトリ内の残存DLLに
   依存しないことの確認)。
   成立しない場合は前提4のとおりフレームワーク依存発行へ切り替えてから先へ進む。除外リスト `docs/guides/package-excluded-packages.txt` を作成し、ホスト・
   ブリッジ両プロジェクトの `dotnet list package --include-transitive --format json` の
   和集合(除外適用後)と、各パッケージの同梱ライセンス・NOTICE類(他に同梱ファイルが
   無いことも確認)、必要なSPDX標準本文(`docs/guides/licenses/` へ転記)、ビルドSDK同梱の
   LICENSE.txt・ThirdPartyNotices.txt から、照合ブロック付きの
   `docs/guides/package-thirdparty.txt` を作成規則どおりに作成する。
2. `Directory.Build.props` へ `Version`(0.1.0)を定義し、ホスト・ブリッジが共有することを
   確認する。`scripts/package.ps1`(発行→zip→内容物検査)を作成し、`dist/` を `.gitignore` へ
   追加する。パッケージ生成検査を検証手順書へ登録する。
3. `docs/guides/package-readme.txt`(利用者向け手順の正本テンプレート)を作成し、READMEへ
   概要とリンクを追記する。
4. 生成したパッケージを用い、READMEテンプレートの手順どおりに実機確認する(既存の
   開発用登録がある場合は一旦解除してから行い、確認後に元へ戻す): (a)新規導入
   (zip展開→DLL配置→MCP登録→エディタ起動→ping応答)。(b)更新手順(手順どおりの
   停止→上書き→再起動→ping応答)。(c)エディタを起動し直しても登録の操作が要らないこと
   (エディタを終了して起動し直し、`claude mcp` の操作なしにping応答で確認)。(d)アンインストール手順(実行後に `claude mcp list`
   の登録・`_plugin\User` のDLL・展開フォルダが消失していること)。結果を進捗ドキュメントへ
   記録する。
5. 全検査を実行して成立を
   確認し、進捗ドキュメントへ実行コマンドと合否を記録する。完了後、本計画書を削除候補
   として報告する(削除の実行はユーザーの指示があったときのみ)。

## 完了条件

- `pwsh scripts/package.ps1` の1コマンドで配布パッケージが生成され、内容物検査を通過する。
- READMEテンプレートの手順どおりの新規導入・更新・エディタ起動し直し後の再登録不要・
  アンインストールを実機のPMXエディタ+Claude Codeで確認済みである(新規導入と更新は
  `ping` 応答、アンインストールは登録・DLL・展開フォルダの消失まで)。
- パッケージ生成の検査が検証手順書へ登録され、READMEが `README.txt` テンプレートを案内して
  いる。
- 全検査が成立している。
