## 記録規則

- 実装は計画書01から番号順に進める。各ステップの完了時にチェックを付け、実行記録へ
  「ステップ・実行したコマンド・合否」を追記する。
- 計画書は実装完了後に削除される前提のため、本文書から**計画書ファイルへのMarkdown
  リンクを張らない**(計画書名はテキストとして記録する)。
- 本文書には進捗の事実だけを記録する(設計値・手順を書かない。正本は各仕様書・
  検証手順書)。
- 中断するときは引き継ぎ記録へ「現在位置・未解決事項・次の作業」を残す。

## 実行記録

形式: ステップ / 実行コマンド / 合否

| ステップ | 実行コマンド | 合否 |
|---|---|---|
| 01-1 | `dotnet new sln -n PmxEditorMcp --format sln` | 成功 |
| 01-2 | `dotnet build PmxEditorMcp.sln -warnaserror` | 不成立(下記参照) |
| 01-2 | `dotnet format PmxEditorMcp.sln --verify-no-changes` | 合格 |
| 01-2 | `dotnet test PmxEditorMcp.sln` | 合格 |
| 01-3 | `node --check scripts/e2e-check.mjs` | 合格 |
| 01-4 | 実行コマンドなし(検証手順書の書き換え) | 完了 |
| 01-5 | 上記4検査の再実行 | ビルド以外は合格 |

ビルド検査は、ソリューションにプロジェクトが1本も無いと復元段階が警告を出し、`-warnaserror` が
それをエラーへ昇格させるため成立しない。プロジェクトを1本追加すればこの警告自体が出なくなる
ことは実測済み。検査の定義は据え置き、ビルド検査の初回の成立確認は実装計画書02が担う。
