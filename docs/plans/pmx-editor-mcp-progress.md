# pmx-editor-mcp 実装進捗

実装計画書01〜06の実行状況を記録する。新規の作業者(エージェント)はこの文書だけで
現在位置を把握し、続きから作業を引き継ぐ。

## 記録規則

- 実装は計画書01から番号順に進める。各ステップの完了時にチェックを付け、実行記録へ
  「ステップ・実行したコマンド・合否」を追記する。
- 計画書は実装完了後に削除される前提のため、本文書から**計画書ファイルへのMarkdown
  リンクを張らない**(計画書名はテキストとして記録する)。
- 本文書には進捗の事実だけを記録する(設計値・手順を書かない。正本は各仕様書・
  検証手順書)。
- 中断するときは引き継ぎ記録へ「現在位置・未解決事項・次の作業」を残す。
- 受入検証の実行識別子は、下記「受入検証の実行識別子」の節へ値だけを記録する
  (生成・初期化・照合の手順と値の形式は検証手順書が正本)。

ことは実測済み。検査の定義は据え置き、ビルド検査は実装計画書02のステップ1で初めて成立した。

合否の内訳(警告数・テスト件数など)は、実行出力が残っている 02-7 の行にだけ記した。それより前の
行は、当時の出力が残っていない。

    仕様書の確定値と違う場所として書いている。

    でも、浅い配列へ空のオブジェクトを大量に並べれば、解析でその数だけオブジェクトが作られ、
    エディタと同じプロセスのメモリを圧迫できる。上限を設けるかどうかと、その値は、ツール契約が
    集合を対象に取る要求でどれだけの要素を許すかと関わるため未決。
