# 実装計画書06: 結合・受入検証

先行するすべての実装計画書の成果物がそろった状態で、システム全体の結合を受入シナリオで検証し、
恒久文書の整合を最終確認して、実装フェーズを完了させる。本計画の結果はすべて進捗
ドキュメント(`docs/plans/pmx-editor-mcp-progress.md`)へ記録する。

## 前提と裏取り

1. **前段の完了**
   - 出典: 進捗ドキュメントの完了記録
   - 確かめた結果: 本計画は先行するすべての計画の完了条件が満たされた状態で開始する(検査体系・
     ホスト・ブリッジ・全ツール・配布パッケージが存在し、各計画の実機確認が済んでいる)。
     未達の計画があれば本計画は開始できない——開始条件として progress の記録で確認する。
2. **検証環境**
   - 出典: READMEの開発環境(05でPowerShell 7を追加)
   - 確かめた結果: 必要環境はREADMEが正本であり、本計画は新しい環境要件を追加しない。
3. **受入の判定基準**
   - 出典: 能力台帳(提供全能力)とツール契約のシグネチャ単位ゲート・行単位の自動E2E検査
   - 確かめた結果: 個別ツールの行単位の合否は、ツール契約が整備した自動E2E検査(実機エディタに
     対して自動実行するもの)と、イベント行の payload 変換を網羅するxUnitテストが判定済みで
     ある(行ごとに何がどこまで確かめられるかはツール契約が定めた保証の境界による)。本計画の受入シナリオは「代表的な利用の流れが
     結合状態で成立すること」を確認するもので、行単位の網羅確認を置き換えない(照合ゲートと
     検査記録の網羅の再実行でその状態を検証する)。

## 仕様書とコードの食い違い

本計画の作成時点ではプロダクトコードは未実装である(実行時には先行するすべての計画の成果物が
存在する)。突き合わせ範囲: アーキテクチャ仕様書・IPC仕様書・実装計画書04・05・検証手順書・
能力台帳の全文。食い違いは無い。

## 確定する設計値

### 一括検証と文書整合(進捗ドキュメントへ記録)

- **全検査の一括実行**: 検証手順書の検査一覧(ビルド・整形・テスト・スクリプト構文・
  PowerShell構文・パッケージ生成・照合スクリプト・**自動E2E検査**・**MCP経路の2検査**
  (群単位の検索での発見可能性/宣言あり・なしのA/B対照による宣言の有効性))を
  すべて実行し、
  全合格を確認する。自動E2E検査は実機のエディタを起動した状態で1コマンド実行する
  (`scripts/e2e-tools.mjs`)。
- **長時間放置後のコネクタ再利用の確認**: `--soak` 経路を1回実行する(通常の一巡には
  含めていない)。所要8時間の待機を含み、通常の一巡は最終段でエディタを終了させるため、
  **他の検査と同じエディタインスタンスを共有せず、単独で先に完走させてから**上記の一括実行に
  進む。**エディタの起動・終了順序を次のとおり一意に定める**: (1)シナリオ9まで残っているエディタを
  終了する。
  (2)この検査専用にエディタを1つ起動する。(3)`--soak` を完走させる。(4)そのインスタンスを
  終了する。(5)一括実行のためにエディタを起動し直す。
- **網羅の再確認**: 照合ゲート(シグネチャ集合・能力対応表・スキーマ・型役割・
  除外一覧・危険操作三者一致)と、行単位・経路キーの検査記録の網羅(全行が**自動E2E合格・
  イベント行の payload 変換をxUnitで全行網羅**のいずれかで
  あること・未分類ゼロ・不合格ゼロ・イベントの代表発火がリスナ型の集合と、画像の
  確認が画像を返すツールの集合と、それぞれ完全一致すること)を再実行して
  確認する(ツール群実装の完了時からの乖離検出)。
- **文書整合の最終確認**: 対象は**Git追跡下の全恒久文書**(README と `docs/` 配下の
  全ファイル。除外はその時点で存在する計画書 `docs/plans/pmx-editor-mcp-plan-0*.md` のみで、
  **進捗ドキュメントは対象に含める**)とし、列挙漏れを防ぐ(IPC仕様書・型役割表等の
  機械可読正本・第三者ライセンス正本も自動的に対象へ含まれる)。検査は次の2つを確定する:
  (a)**計画書参照の残存検査**: 対象ファイル(進捗ドキュメントを含む)に対して文字列
  `pmx-editor-mcp-plan-0` のMarkdownリンクが無いことを検査する(進捗ドキュメントは
  計画書名をテキストとして記録してよいが、削除後に切れるリンクは張らない——この記録
  規則も進捗ドキュメントの冒頭に明記する。進捗以外の恒久文書は文字列ヒット0件を合格と
  する)。
  (b)**リンク切れ検査**: 対象Markdownファイルの相対パスリンクを抽出し、リンク先
  ファイルの存在を検証するスクリプト `scripts/check-doc-links.ps1`(本計画のステップで
  作成)を実行し、欠落0件を合格とする。
  両検査は実行コマンド・合格条件つきで検証手順書へ登録する。

### 完了処理

- 本計画書を**削除候補としてユーザーへ報告する**(削除は行わない。削除の実行はユーザーの

## 実装ステップ

1. 開始条件を確認する(進捗ドキュメントで先行するすべての計画の完了記録を確認。未達があれば
   その計画へ戻り、未達の項目を終えてから本計画を始める)。
2. 操作役のスクリプトへ `undo`・`click`・`show` を実装する。
3. 検証手順書の受入シナリオを、ツール仕様書の確定値でツール名・引数まで具体化する。
4. 検証手順書の受入シナリオを実機で実行する。結果を進捗ドキュメントへ記録する。不合格が
   あれば検証手順書の復元の手順に従って再実行する。
5. `scripts/check-doc-links.ps1` を作成して文書整合の2検査を検証手順書へ登録し、
   文書整合の最終確認(リンク切れ・計画書参照の残存)を実行して結果を進捗ドキュメントへ
   記録する。
6. **最終状態で** `--soak` 経路を単独で実行し(所要8時間。他の検査と同じエディタ
   インスタンスを共有しない)、合否を進捗ドキュメントへ記録する。完走後に全検査の一括実行
   (文書整合の検査で追加したスクリプト・検査を含む)と網羅の再確認を行い、結果を進捗ドキュメントへ
   記録する。
7. 本計画書を削除候補としてユーザーへ報告する(削除はしない)。
