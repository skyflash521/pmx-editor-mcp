# 共通契約仕様書

すべてのツールが共有する契約を定める。**ツールの結果をどう返すか**・**要求の大きさをどう限るか**・
**値をどうJSONへ写すか**・
**編集をどう分けるか**・**対象の集合をどう指すか**・**一覧をどう区切るか**・**取り返しの付かない呼び出しをどう断るか**・
**Undoをどう抑止するか**・
**長寿命のオブジェクトをどう指すか**・**イベントをどう渡すか**と、
個別のツールを持たず共通契約の側が受け持つSDKのシグネチャについて**どこへ割り当てるか**・
**引数・戻り値・レシーバーを何へ束縛するか**を持つ。割当の値の正本は
[共通契約割当の正本](pmx-editor-mcp-common-assignments.json)で、規則と検査はこの文書が持つ。

## ツールの応答

ツールの結果は**包み**で返す。成功は値を、失敗はエラーコードと説明を持ち、どちらも警告を伴える。
対象はツールが呼ぶメソッドで、ホスト基盤が受け持つメソッド(`handshake`・`ping`)は包みを返さない
——これらはツールの結果ではなく、接続そのものの成立を確かめるものだからである。

| 項目 | 成功 | 失敗 |
|---|---|---|
| `ok` | `true` | `false` |
| `value` | ツールの値(値を持たないツールは `null`) | 持たない |
| `error` | 持たない | `code` と `message` の組 |
| `warnings` | 文字列の並び。無いときは持たない | 同じ |

**ドメインの失敗をこの包みで返す**のは、JSON-RPCの `error` を要求の解釈・ディスパッチ・応答生成と
いったホスト基盤の異常のために空けておくためである。**警告は在るときだけ載せる**——空の並びを
載せると、警告が無いことを表す形が2つになる。**`message` と警告の各要素は空にできない**
(空白だけも不可)——中身の無い説明は、読み手にとって説明が無いのと同じである。

### ツールエラーコード

`error` の `code` は次の8つで閉じている。

- `TOOL_INDEX_OUT_OF_RANGE`: 範囲外の位置を指した。
- `TOOL_INVALID_ARGUMENT`: 引数の値が不正。
- `TOOL_INVALID_HANDLE`: ハンドルが不正。
- `TOOL_CONFIRM_REQUIRED`: 危険操作の確認が無い。
- `TOOL_NOT_APPLICABLE`: 現在の状態・提供範囲で適用できない。理由を説明に含める。
- `TOOL_OPERATION_FAILED`: 実行に失敗した。例外の内容と、状態がどうなったかを説明に含める。
- `TOOL_RESPONSE_TOO_LARGE`: 応答が応答サイズ予算に収まらない。
- `TOOL_REQUEST_TOO_LARGE`: 要求が要求サイズ予算に収まらない。

### 応答サイズ予算の分け方

[応答サイズ予算](pmx-editor-mcp-architecture.md#応答サイズ予算の設定)は**本文**の文字数の上限で、
その内訳は**値の枠**と**警告の枠**の2つとする。本文とは、下記の結果のテキストから接続先を名乗る行を
除いた部分をいう。

- **警告の枠は2,000文字**。警告そのものに加えて、1件ごとに本文で伴う行の区切りと `警告: ` の
  接頭辞、そして切り詰めた旨の注記も、この枠の中に収める。
- **値の枠は予算から警告の枠を引いたもの**。
- 警告が枠に収まらないときは、**切り詰めた旨の注記を末尾へ置いた形が枠に収まるところまで前から
  採る**。警告を落とすのは、警告のために値を削るとツールの結果そのものが失われるからである。
- **値が値の枠に収まらないときは**[応答が大きすぎる](#ツールエラーコード)**として断る**。
  [一覧](#一覧)は件数を減らして返す道を持つので、そちらの規則が先に当たる。

### MCPクライアントへ返す結果

ブリッジが包みを結果へ写す。**包みそのものはクライアントへ見せない**。

- 結果は**テキスト1件**とし、接続先を名乗る行に続けて本文を置く。本文は、成功なら `value` の
  JSON表記、失敗なら `コード: メッセージ` とする。警告があれば本文の末尾へ `警告: ` で始まる行として
  足す。**画像を返すツールだけは、画像を先頭に置いてからそのテキストを続ける**。
  ドメインの失敗にも接続先の行を置くのは、呼び出しが成立して接続先の知らせを消費するからである
  ——ここで捨てると、接続先が変わった事実がどの応答にも現れなくなる。
- **公開する出力スキーマが述べるのは `value` の構造**である。包みを見せない以上、呼び出し側が
  受け取る形はそれだけになる。
- 失敗は結果の誤りの印を立てる。
- **本文が予算を超えていたら、本文を返さず `TOOL_RESPONSE_TOO_LARGE` の誤りにする**。値の枠と警告の
  枠はホストが守るので、ここで超えるのはホストが見落としたときだけである——最後の砦として置く。
- **包みとして読めない応答は、ホストの応答が契約から外れているものとして扱い、接続を捨てる**
  ——成否を持たない、成功なのに値が無い、失敗なのに誤りの内容が空、警告が空でない文字列の並びで
  ない、のいずれもここで落ちる。契約から外れた応答を返す相手とは、次の要求の応答も対応づけられない。

## 要求サイズ予算

要求の大きさの上限は**8,000,000バイト**とする。[IPCが運べる16MiB](pmx-editor-mcp-ipc.md)のおよそ
半分で、上限いっぱいを常用しないための余白をこの差が受け持つ。**設定では変えない**——受け取る側の
事情ではなく名前付きパイプが運べる量から決まる値で、設定にするとホストとブリッジで食い違って
受理できる件数がずれる。**応答と単位が違う**のは、限るものが違うからである——応答を限るのは
受け取るMCPクライアントで、数えるのは文字数になる。要求を限るのは名前付きパイプで、数えるのは
バイト数になる。

**ツールは、受け取った要求のUTF-8のバイト数がこの予算を超えていたら、実行せずに**
[要求が大きすぎる](#ツールエラーコード)**として断る**。説明には要求の大きさと予算を含める。状態は
[未変更](#編集の分類)である。判定はツールの処理の最初に置き、**[Undoの抑止](#undoの抑止)が
覚えた残留を戻しにいくより前**に済ませる——戻しにいくのはSDKを呼ぶことなので、先に断れば
SDKへ触れないまま状態が未変更であることが保てる。したがって**予算を超えた呼び出しでは残留を
戻しにいかず、戻したことの警告も載らない**。ホスト基盤が返す誤りはこの判定より先に立ち、
ツールでないメソッドはこの判定を持たない。

## 値の表現

ツールの引数と応答に現れる型のうち、**値そのものとしてJSONへ写す型**の写し方をここで定める。
役割を持つ型は載らない——それらは値として写さず、
[型役割仕様書](pmx-editor-mcp-type-roles.md)が定める役割ごとの扱いに従う。
**下記の型ごとの表に載るのは値として写せる型のすべて**で、載っていない型を値として写す道は無い。

### 表現の綴り

| 綴り | JSONの形 |
|---|---|
| `boolean` | 真偽 |
| `number` | 数値 |
| `text` | 文字列。`System.Version` は標準の表記とする |
| `base64` | バイト列をBase64で詰めた文字列 |
| `enum_name` | 列挙子名の文字列 |
| `number_array` | 成分を順に並べた数値の配列。並びは下記のとおり型で決まる |
| `color` | `[r, g, b]` または `[r, g, b, a]`。成分は0以上1以下の数値とする |
| `size` | `[幅, 高さ]` |
| `point` | `[x, y]` |
| `rectangle` | `[x, y, 幅, 高さ]` |
| `font` | `family`(書体名の文字列)・`size`(数値)・`style`(列挙子名)を持つ組 |
| `brush` | 色の配列。ホストはその色の単色ブラシを組み立てる |
| `image` | Base64で詰めた画像。形式は[画像](#画像)が定める |
| `json` | 任意のJSON値。null・真偽・数値・文字列・配列・組を再帰的に組み合わせた形を許す |
| `null_value` | JSONの null |

`number_array` の並びは型で決まる。`PEPlugin.SDX.V2` は `[x, y]`、`PEPlugin.SDX.V3` と
`PEPlugin.Pmd.IPEVector3` と `SlimDX.Vector3` は `[x, y, z]`、`PEPlugin.SDX.V4` と
`PEPlugin.SDX.Q` と `PEPlugin.Pmd.IPEQuaternion` と `SlimDX.Quaternion` は `[x, y, z, w]`、
`PEPlugin.SDX.M` と `SlimDX.Matrix` は**行優先の16要素**とする。

`json` はホストがJSON値と行き来できる形で持つ。**取った値がJSONで表せない.NETのオブジェクトだった
ときは、値を返さず**[適用できない](#ツールエラーコード)**として断る**——表せない旨を説明に含める。
`null_value` は、出力スキーマの側でもnullの型として書く。

### 画像

`image` の綴りが指す画像は、次のとおりやり取りする。

- 送り出す画像は**PNG**とする。**長辺が `maxLongSide` を超えるときは、縦横比を保って縮める**。
  長辺をその値へそろえ、短辺は比で求めて四捨五入し、1を下回らせない。縮めたときは、元の大きさと
  縮めた後の大きさを警告に載せる。
- `maxLongSide` は**既定512・最小256・最大2048**とする。画像はほかの値より桁違いに大きくなりうるので、
  量を大きさで抑える。既定を小さめに置くのは、受け取る側が画像をどう数えるかが分かっていない
  からである。**それでも最小の256を既定にしないのは、内容を判別できる大きさを既定のまま保つため**で、
  足りなければ呼び出す側が `maxLongSide` で最大まで引き上げられる。
- 受け取る画像は**PNGかBMP**に限り、辺は**4096まで**とする。ホストは32bitのARGBへ直してから使う。
  Base64として読めないもの・画像として読めないもの・形式が違うもの・辺が上限を超えるものは、いずれも
  [引数が不正](#ツールエラーコード)として扱う。

### 包む型

配列と `System.Collections.Generic.IList<1>` は、要素の表現を `array_of_` で包む。ただし
**一列に並ぶバイトは `base64`** とする——多次元では各次元の長さが失われるので、そこは包む規則へ
倒す。`System.Nullable<1>` は、要素の表現を `nullable_` で包む。

### 表の形

行は**2列**とし、型の欄は綴りを `` ` `` で囲む。表現の欄は、綴りが1つに決まる型ではその綴りを同じく
囲み、要素の表現を包む型では囲まない——囲んだ綴りだけを表現として読むので、包む型に綴りを書けば
その1つに決めたことになる。同じ型は二度現れない。

### 表の検査

値の表現の照合が、次を検査する。

- 表の型が、**値として写せる型と過不足なく一致すること**。載せ落とした型も、値として写せない型を
  足したのも、ここで落ちる。
- 綴りが1つに決まる型の表現が、**規則が導く綴りと一致すること**。
- **要素の表現を包む型に綴りが書かれていないこと**。

## 編集の分類

分類が付くのは**ツールの呼び出し**で、ツールそのものではない。**対象の指し方で作用の仕方が変わる
ツールは、指し方ごとに別の分類に当たる**——いまの状態を複製して反映する指し方と、実体を受け取って
直に触る指し方とでは、確定させる呼び出しが別のものになるからである。

エディタの状態か外部へ作用する呼び出しは、次の3つのどれか1つに当たる。**上から順に見て、最初に
当たった1つ**とする。

- **複製編集型**: いまの状態を複製して変え、まとめて反映するもの。
- **直接変更型**: 上に当たらないもののうち、モデルのデータ・長寿命のオブジェクト・ファイルへ直に
  作用するもの。
- **表示・セッション型**: 上のどちらにも当たらないもの。表示と設定とセッションだけを動かし、
  モデルのデータにも長寿命のオブジェクトにもファイルにも作用しない。

どちらへも作用しない呼び出しは**読み取り**とし、上の3つのどれにも当たらない。分類の値はこの
読み取りを合わせた4つで閉じている。

どの分類も、処理の全体を**ひとつながりのUIスレッドの呼び出しの中で**行う。途中にエディタの手動の
操作が割り込まない。

**反映を確定させる呼び出し**は分類で決まる。複製編集型はまとめて反映する呼び出し、直接変更型は
そのSDK呼び出しの正常な返却、表示・セッション型は同じくその呼び出しの返却である。失敗したときに
エディタの状態がどうなっているかは、その呼び出しを境にして決まる。

| 失敗した位置 | 状態 | 呼び名 | 返し方 |
|---|---|---|---|
| 確定させる呼び出しへ入る前 | 変わっていない | 未変更 | 誤り |
| 確定させる呼び出しそのもの | 変わったかどうか分からない | 結果不明 | 誤り。その旨を本文へ含める |
| 確定した後 | 変わっている | 変更済み | 警告を添えた成功 |

**確定した後に失敗しうるのは複製編集型だけ**である。反映のあとに表示を更新する段があり、そこが
失敗しても反映は取り消せない。ほかの2つは、確定させる呼び出しが返ったところで終わる。

**結果を受け取れないまま呼び出しが終わったときの状態は、要求をホストへ送る前か後かで決まる**。
送る前に終わったもの——待ち行列・接続の確立・ハンドシェイクの途中——は変わっていない。送った後に
終わったもの——処理タイムアウト・送信の後のキャンセル・接続の切断——は変わったかどうか分からないので、
読み取りのツールで確かめる。

## 対象の集合

集合を対象とするツールは、**1件ではなく集合**を受け取る。指し方は次の4つで、**2つ以上を同時に
持つことも、1つも持たないこともできない**。

- `indices`: 位置の整数の配列。**位置は0以上で、対象のリストの件数より小さい**。
- `range`: `start`(最小0)と `count`(最小1)の組。
- `all`: 真。対象のリストの全要素を指す。
- `handles`: [ハンドル](#ハンドル)の配列。ハンドルが指す対象——まだリストへ加えていない生成物や、
  リストの外で生きる長寿命のオブジェクト——を指す。

`range` の項目名を[一覧](#一覧)の `offset`・`limit` と分けるのは、指すものが違うからである
——こちらはリストの位置、あちらは解決した集合の位置を指す。

**ここが定めるのは1つの集合の指し方である**。1つの要求が2つ以上の集合を指すこともあり、そのときは
集合ごとにこの規則が働く。**項目名は指す対象ごとに分ける**ので、どの項目がどの集合のものかは名前で
決まる——同時に持てないのは同じ集合を指す指し方どうしであって、別の集合を指す項目とは重ならない。
位置でもハンドルでも指せない対象を持つ集合は、その指し方を各ツールが自分の仕様で定める。その場合も
**空にできないこと・同じものを二度以上指せないこと・要求に現れた順で解けること**は同じく守る。

どの指し方を受け付けるかはツールごとに決まる。**その配列が空だと対象が決まらない配列は、空に
できない**——この節では `indices` と `handles` がこれに当たり、空の配列は引数が不正として断る。
対象を指す働きを持つほかの配列にも同じことが当てはまる。長さが対象の件数に従う配列(要素ごとの
値・引数の並び)には課さない。対象が0件なら空が正しいからである。

**同じ要素を二度以上指す指定も断る**。取り除いて先へ進めると、指定した配列の長さと要素ごとの値の
並びの長さが食い違う。ハンドルの重複では、1件目が消費された時点で2件目が必ず失敗する。要求の
誤りとして、解決の前に返す。

**解決した集合の順序**は、並びのある指し方(`indices`・`handles`)では要求に現れた順、並びを
持たない指し方(`range`・`all`)ではリストの位置の昇順とする。要素ごとの値・引数の並びは、この順で
対象へ対応づく。[一覧](#一覧)の `offset` と `limit` は、解決した集合に対して働く。

**断り方は、何が誤っているかで決まる**。

- **指し方そのものの誤り**は[引数が不正](#ツールエラーコード)とする。2つ以上・1つも無い・その
  ツールが受け付けない指し方・空の配列・同じ要素を二度以上指すこと・`range` の `start` が0を
  下回るか `count` が1を下回ることが、これに当たる。
- **位置がリストの外にある**ときは[範囲外の位置](#ツールエラーコード)とする。`indices` の位置が
  0を下回るときも、リストの件数以上のときも、`range` の指す末尾がリストを越えるときも同じである。
- **`handles` に使えないハンドルがある**ときは[ハンドルが不正](#ツールエラーコード)とする。

### 部分適用をしない

**検証は適用の前にすべて済ませ、途中まで適用した状態を残さない**。対象の解決——位置が範囲の中に
あること、ハンドルが使えること——と、値・引数の全項目の検証を、対象の全件について先に行う。
**1件でも不正なら何も変えずに断り**、状態は[未変更](#編集の分類)とする。値・引数の全項目の検証と
は、**項目の名前が知られたものであること・値がその項目の取りうる範囲に収まること・参照の位置が
リストの中にあること・nullを許さない項目にnullが来ていないこと**を見ることをいう。

- 全件へ同じ値・引数を使う指定は、**対象の件数によらず1度は全項目を検証する**。対象がたまたま
  0件でも省かない——要求の値が不正であることは対象の件数と関わりなく決まるので、空のときだけ
  通るのは一貫しない。
- 要素ごとの値・引数の並びは対象と同じ長さなので、対象0件では検証も0回になる。
- **直接変更型の呼び出しにも同じく課す**。複製を介さないので、適用より前に済ませない限り途中まで
  適用された状態が残る。

## 一覧

一覧を返すツールは、**どこから何件か**を受け取り、**総数・切り出した並び・続きの位置**を返す。

- 受け取るのは `offset`(既定0・最小0)と `limit`(最小1)。負の数・整数でないもの・範囲の外は
  [引数が不正](#ツールエラーコード)として断る。`limit` の既定と最大は、要素型によって1件あたりの
  大きさが違うので共通には決まらない。**各ツールが自分の仕様で定める**。
- 返すのは `total`(切り出す前の総数)・`items`(切り出した並び)・`nextOffset`(続きがあるときだけ)。
- **`offset` が `total` 以上のときは、空の `items` を正常として返す**。位置が末尾を越えていることは
  誤りではない。
- 組み立てた値が[値の枠](#応答サイズ予算の分け方)に収まらないときは、**収まる件数まで減らして
  返す**。枠に照らすのは `items` だけでなく、`total` と `nextOffset` を含む値の全体である。
  減らしたときは、減らす前に切り出せた件数と返した件数を警告に載せ、`nextOffset` は返した件数の
  ぶんだけ進める。**1件も返せないときは**[応答が大きすぎる](#ツールエラーコード)として断る。

[イベント](#イベント)の取り出しはこの規則の対象外とする。溜まったものを古い順に渡す形なので、
位置で区切らず、続きの位置も持たない。

## 危険操作

取り返しの付かない呼び出しは、**呼び出す側の確認を求める**。確認は共通引数 `confirm` を真に
して示し、**無ければ実行せずに**[確認が要る](#ツールエラーコード)として断る。確認を要するのは
次の3つとする。

- **エディタ終了**: エディタそのものを終わらせるもの。
- **上書き保存**: ファイルへ書き込むもの。上書きになるかどうかは問わない——書き込む先が既に
  あるかは、呼ぶ前には分からない。
- **モデル初期化**: 開いているPMXの中身を一度に空にするもの。別の内容を読み込んで置き換えるものは、
  空にするのではないので当たらない。

どのシグネチャが当たるかは名前で決める。意味の近い別のメンバーを巻き込まないよう、**名前だけで
決めてよいものと、宣言型と組で名指しするもの**を分ける。

- エディタ終了は、`PEPlugin.Form.IPEFormConnector` の `Close`。
- 上書き保存は、**メンバー名が `Save` で始まるものと `ToFile`**。提供対象には、この名前で
  ファイルへ書き込まないメンバーも、この名前以外でファイルへ書き込むメンバーも無い。
- モデル初期化は、`PEPlugin.Form.IPEFormConnector` の `InitializePMD` と `InitializePMX`、および
  `PEPlugin.Pmx.IPXPmx` の `Clear`。名前が同じでも、ほかの型の `Clear` は当たらない。

`PEPlugin.Pmx.IPXPmx` の `Clear` だけは、**呼ぶ対象で要否が分かれる**。開いているPMXを対象に
呼ぶときは確認を要し、対象を指定して呼ぶときは要さない——後者が空にするのはエディタが開いている
ものではなく、メモリの上に作った生成物だからである。

[能力台帳](pmx-editor-mcp-capability-ledger.md)は同じシグネチャを備考へ記す。上の決め方が導くものと
台帳が記すものが、集合としても種別としても食い違わないことを検査する。**検査はシグネチャ単位で
行う**ので、呼ぶ対象による上の分かれ方は検査に現れない。

## Undoの抑止

編集をエディタのUndoへ積まないようにできる。積むかどうかはエディタの側の記録なので、止めたまま
放置すると、以後の編集をどれも戻せなくなる。そこで次を規則とする。

- 止めたら、**編集の成否や例外によらず必ず戻す**。止める呼び出しそのものが失敗したときは、
  止まっていないものとして扱い、戻さない。
- 戻せなかったときは、**その場で1度だけやり直す**。
- それでも戻らなかったときは、**戻せていないことを覚える**。覚えるのは接続をまたぐ1つの状態と
  する——止まっているのはエディタの側なので、接続が切れても直らない。後から戻せたときに、覚えた
  ことを消す。

**[複製編集型](#編集の分類)がまとめて反映するのは、1呼び出しにつき1回**とする。抑止はその呼び出しの
中の登録を止めるだけで、**呼び出しをまたぐ編集を1つへまとめる手段は持たない**。

**止めることを頼めるのは[複製編集型](#編集の分類)の呼び出しだけ**とし、ほかの分類が頼んだら
[引数が不正](#ツールエラーコード)として断る。止めても効くのはまとめて反映するときのUndoの登録に
限られるので、その反映を持たない呼び出しでは頼んでも何も起きない。

**戻せていないことを覚えている間は戻しにいく**。試みるのは、**ツールの呼び出しの冒頭・接続が
終わるときの後始末・新しい接続のハンドシェイクの直後**の3つとする。戻せたら、以後の最初の応答に
警告で知らせる。呼び出しの冒頭で戻せなかったときの扱いは分類で分かれる。

- **複製編集型と直接変更型は、実行せずに**[実行に失敗した](#ツールエラーコード)**として断る**。
  止まったままの状態でエディタの側を変えると、その変更をどれも戻せなくなる。断るので状態は
  [未変更](#編集の分類)である。
- **表示・セッション型と読み取りは実行し、応答へ警告を添える**。エディタの側を変えないので、
  止まったままでも失うものが無い。

**戻せていないことを覚えたら、それを作った呼び出しの応答にも載せる**。成功なら警告として、失敗なら
誤りの説明へ足す。覚えたことが呼び出し側へ伝わらないと、次の編集を戻せない理由が分からない。

## ハンドル

PMXの状態の外で生きるSDKのオブジェクト——UIモデル・イベントコネクタ・イベントリスナ・テキスト
コントロール・ビルダの生成物——は、**ホストが台帳で保持し、ツールはハンドルIDで参照する**。実体を
やり取りせずIDで指すので、ツールの引数と応答は値だけで書ける。

- **IDは接続ごとの正整数**で、1から順に増える。使い回さない。
- **所有者はホスト**。ツールは実体を受け取らず、台帳を通してだけ触る。
- ハンドルは**生成に関与したハンドル**(依存元。複数でもよい)を覚える。UIモデルのイベント
  リスナが、生成元のUIモデルと引数に取るイベントコネクタの両方に依存するような場合である。
- **解放は子から依存元の順**で行う。依存元を解放すると、それに依存するものを先に解放して
  失効させる——先に依存元を手放すと、子の解放が拠り所を失う。
- **解放の仕方は型ごとに違う**ので、発行するときに決めて台帳が覚える。
- 台帳が知らないID・解放済みのID・**期待する型と違う**ハンドルは、いずれも使えないハンドルとして
  同じに扱う。どれであるかを返すと、台帳の中身を呼び出し側へ教えることになる。二度目の解放も
  ここで落ちる。
- **解放が例外になっても失効させ、後続の解放は続ける**。SDKの側がどうなったかは分からないので、
  そのハンドルは失敗したものとして呼び出し側へ知らせる。途中で止めると、解放できたはずのハンドルが
  台帳に残る。
- **まとめて解放できる**。接続が終わるときに、残っているハンドルを同じ順序の規則で解放し、**台帳を
  閉じる**。閉じた台帳は発行を受け付けない——解放を走らせている間に発行できると、そのハンドルが
  誰にも解放されないまま残る。
- **結果を破棄する呼び出しが発行したハンドルは、破棄するときに解放して失効させる**。破棄するのは
  [処理が上限の時間を超えたとき・処理が例外で終わったとき・応答を組み立てられないか大きすぎる
  とき](pmx-editor-mcp-ipc.md#エラーと切断の規則)である。同じ順序の規則で解放し、台帳は閉じない。
  呼び出し側へ届かないIDを残すと、誰も解放できないまま接続の終わりまで居座る。

## イベント

購読しているイベントは**取りに来たぶんだけ渡す**。押し出す通知は持たない——ツールの呼び出しと同じ
向きだけでやり取りするので、受け取り側は自分の都合で読める。

- イベントは**接続ごとに溜める**。溜められるのは1000件までで、超えたら**古いものから捨てる**。
- 各イベントは、**接続の中で1から増える連番** `seq`・イベント種別の識別子 `type`・そのイベントを
  購読しているリスナのハンドルID `sourceHandle`・イベント固有の値 `payload` を持つ。
- 取り出しは**古い順**に、指定した件数まで。件数は `limit` で受け取り、既定100・最小1・最大1000と
  する。負の数・整数でないもの・範囲の外は[引数が不正](#ツールエラーコード)として断る。
- 取り出しの結果は、取り出した並び `events` と、**捨てた件数** `dropped`——前回の取り出しから今回
  までに溢れて捨てたぶんで、返したところで0へ戻す——と、**取り出した後に残っている件数**
  `remaining` を持つ。
- 受け取り側は、**連番の欠番と捨てた件数**で取りこぼしを知る。どちらも無ければ、そのイベントの列は
  途切れていない。

## 割当

共通契約が受け持つシグネチャは、次の3つのいずれかへ割り当てる。どれかを1つだけ持ち、対象名を伴う。

- `tool`(ツールへの束縛): 対象名はツールの名前。公開の解放・破棄のように、ツールが受け持つもの。
- `commonArg`(共通引数への割当): 対象名は共通引数の名前。Undoの抑止のように、ツールの引数として
  現れるもの。
- `internalFlow`(内部フローへの割当): 対象名は内部フローの名前。ホストが自分で呼ぶもの。

## 内部フロー

内部フローの名前は次の4つで閉じている。**`internalFlow` の対象名になるのは前の3つ**で、
`releaseHandle` はツールが受け持つので `tool` の側に現れる。

- `duplicateEdit`(複製編集): 現在のPMXを複製し、編集し、反映する流れ。
- `stateRead`(状態取得): 現在のPMXを複製して読む流れ。
- `connect`(接続初期化): ホストの起動時に、接続点と常駐アクセスオブジェクトを得て、それらを使う前に
  要る初期化を済ませる流れ。Cプラグイン連携の入口である接続の根の複製は一次資料が利用非推奨として
  おり、ホストは起動時に一度だけ得て常駐期間中保持し、エディタの終了時に破棄する。
- `releaseHandle`(ハンドル解放): ハンドルを解放し、台帳から失効させる流れ。解放は常にツールを
  通して行い、台帳の失効と依存する子の先行解放に連動させるので、ホストが自分で呼ぶ流れにはしない。

## 束縛先スロット

シグネチャの**戻り値・入力引数・レシーバー**をそれぞれ何へ束縛するかを表す名前。次の10個で閉じている。

- `pmxClone`(PMX複製): 現在のPMXの複製。
- `updateKind`(更新種別): 反映する対象の種別。
- `updateIndices`(更新インデックス): 反映する対象の位置。
- `undoLock`(Undoロックフラグ): 反映のときにUndoを積むかどうか。
- `runArgsClone`(RunArgs複製): 接続の根の複製。常駐するコネクタとモジュールパスはここから取る。
- `modulePath`(モジュールパス): 接続の根の複製を求めるときに渡すホストプラグイン自身の位置。
- `residentObject`(常駐アクセスオブジェクト): ホストが常駐期間中保持するコネクタ。
- `targetHandle`(対象ハンドル): 解放・破棄の対象。
- `owningObject`(所有側オブジェクト): 呼び出しを受けるコネクタ・親オブジェクト。
- `injectedConnector`(自動注入コネクタ): `PXCPlugin.IPXCPluginConnector` 型の引数への常駐コネクタの
  束縛。この型の引数はツールのスキーマへ公開せず、ホストが常駐保持するコネクタを注入する。

**割当ごとに使えるスロットが決まる。** `internalFlow` はその内部フローのスロット、`tool` は
ハンドル解放のスロット、`commonArg` は流れに固有のスロットを持たない。加えて `owningObject` と
`injectedConnector` はどの割当でも使える。流れごとのスロットは次のとおり。

| 流れ | 割当 | 使えるスロット |
|---|---|---|
| 複製編集 | `internalFlow` の `duplicateEdit` | `pmxClone`・`updateKind`・`updateIndices`・`undoLock` |
| 状態取得 | `internalFlow` の `stateRead` | `pmxClone` |
| 接続初期化 | `internalFlow` の `connect` | `runArgsClone`・`modulePath`・`residentObject` |
| ハンドル解放 | `tool` | `targetHandle` |

**どの束縛もシグネチャから機械で決まり、書き手が選べない**。決め方を下に示す。戻り値が
`System.Void` のシグネチャは戻り値の束縛を持たず、静的なシグネチャはレシーバーの束縛を持たない。
**解放・破棄**とは、メンバー名が `Dispose` であるか `Release` で始まるものをいう。

- **戻り値**: [接続の根](pmx-editor-mcp-role-types.md)なら `runArgsClone`。ほかの
  [コネクタ型](pmx-editor-mcp-type-roles.md)なら `residentObject`。`PEPlugin.Pmx.IPXPmx` なら
  `pmxClone`。
- **入力引数**: `PXCPlugin.IPXCPluginConnector` なら `injectedConnector`。`PEPlugin.Pmx.IPXPmx` なら
  `pmxClone`。`PEPlugin.Pmx.PmxUpdateObject` なら `updateKind`。`System.Int32` かその配列なら
  `updateIndices`。`System.Boolean` なら `undoLock`。`System.String` で、戻り値が接続の根なら
  `modulePath`。[ハンドル操作型](pmx-editor-mcp-type-roles.md)なら `targetHandle`。
- **レシーバー**: 引数を持たない解放・破棄なら `targetHandle`。ほかは `owningObject`。

**どのスロットとも決まらない引数・戻り値が1件でもあれば、照合は判定を出さずに止まる**——決め方が
その形を覆えていないので、機械の判断として通すか落とすかを決められない。**入力でない引数**
(`out`・`ref`)もここに当たる——スロットはホストが渡す値と受け取る値を表すもので、呼び出しの側へ
書き戻される引数の置き場を持たない。

## 正本の形

`assignments` を項目に持つ組とする。各項目は次を持つ。

- `signatureKey`: 公開API列挙の行キー。**項目はシグネチャ単位**とする——同名のオーバーロードは
  束縛が異なるので、宣言型とメンバー名だけでは分けられない。
- `assignment`: [割当](#割当)の3つのいずれか。
- `target`: 割当の対象名。`internalFlow` では[内部フロー](#内部フロー)のうち対象名になる3つの
  いずれか、`tool` では
  小文字で始まり小文字と数字と下線だけからなる語、`commonArg` では小文字で始まり英数字だけからなる
  語とする——ツールの名前と引数の名前がそれぞれその形だからである。
- `slotBinding`: 戻り値・入力引数・レシーバーの[束縛](#束縛先スロット)。`return` と `receiver` は
  持つときだけ書き、`parameters` は引数の名前からスロットを引く組とする(引数を持たない
  シグネチャでは空の組)。値は機械で決まるので、[検査](#検査)が導いた束縛と突き合わせる。
- `basis`: そう割り当てた根拠の一文。

項目は行キーの序数の昇順に並べ、同じ行キーは二度現れない。**母集合は提供対象のシグネチャに限る**。
接続の経路そのもの——ホストが接続の根から常駐アクセスオブジェクトへ辿る取得プロパティ——は
[能力台帳](pmx-editor-mcp-capability-ledger.md)が非対応とするので提供対象に入らず、この表は
持たない。辿り方は
[型役割仕様書](pmx-editor-mcp-type-roles.md)の接続の経路が正本である。

## 検査

共通契約割当の照合が、次を検査する。

- 表の各項目の行キーが**提供対象のシグネチャに実在すること**。母集合の外の行キーを書けば落ちる。
- **戻り値がコネクタ型のシグネチャが、すべて表に在り、`connect` へ割り当てられていること**。
  常駐アクセスオブジェクトの取得は独立したツールを作らないので、1件でも表から漏れるとその
  シグネチャの割当先が決まらない。
- **解放・破棄のシグネチャが、すべて表に在ること**。同じ理由による。
- 表の**束縛が、シグネチャの引数・戻り値・レシーバーと過不足なく対応すること**。上の決め方で
  すべての束縛を導き、書かれた束縛と突き合わせる。書き落とした束縛も、余分に書いた束縛も、
  別のスロットへ書いた束縛もここで落ちる。
- 束縛したスロットが、**その割当で使えるスロットであること**。内部フローの取り違えは、そのフローに
  無いスロットを束縛していることで表に出る。
- **解放・破棄のシグネチャと、`targetHandle` を束縛する行が `tool` であり、その対象名が互いに
  揃っていること**。解放をホストが自分で呼ぶ流れへ書き替えると、台帳の失効と切り離された解放に
  なる。対象名は書き手が書く語なので、綴りの揺れをここで一つにそろえる。

**機械で確かめられるのはここまでである。** どの割当に当たるか——ツールが受け持つのか、共通引数に
なるのか、ホストが自分で呼ぶのか——と、その対象名が正しい綴りかは、そのシグネチャを何のために使うかの
判断で、列挙からは決まらない。解放のツールの対象名だけは行どうしで揃っていることを確かめられるが、
