# 共通契約仕様書

すべてのツールが共有する契約を定める。**ツールの結果をどう返すか**・**要求の大きさをどう限るか**・
**値をどうJSONへ写すか**・
**編集をどう分けるか**・**対象の集合をどう指すか**・**一覧をどう区切るか**・
**要素のどの項目を返すか**・**取り返しの付かない呼び出しをどう断るか**・
**Undoをどう抑止するか**・
**長寿命のオブジェクトをどう指すか**・**イベントをどう渡すか**と、
個別のツールを持たず共通契約の側が受け持つSDKのシグネチャについて**どこへ割り当てるか**・
**引数・戻り値・レシーバーを何へ束縛するか**を持つ。割当の値の正本は
[共通契約割当の正本](pmx-editor-mcp-common-assignments.json)で、規則と検査はこの文書が持つ。
あわせて、**提供能力をシグネチャへ展開した表**と**すべてのツールの入出力の形を持つ表**が取る形も
この文書が定める。

## ツールの応答

ツールの結果は**包み**で返す。成功は値を、失敗はエラーコードと説明を持ち、どちらも警告を伴える。
対象はツールが呼ぶメソッドで、ホスト基盤が受け持つメソッド(`handshake`・`ping`)は包みを返さない
——これらはツールの結果ではなく、接続そのものの成立を確かめるものだからである。

| 項目 | 成功 | 失敗 |
|---|---|---|
| `ok` | `true` | `false` |
| `value` | ツールの値(値を持たないツールは `null`) | 持たない |
| `error` | 持たない | `code` と `message` の組 |
| `warnings` | 文字列の並び。無いときは持たない | 同じ |

**ドメインの失敗をこの包みで返す**のは、JSON-RPCの `error` を要求の解釈・ディスパッチ・応答生成と
いったホスト基盤の異常のために空けておくためである。**警告は在るときだけ載せる**——空の並びを
載せると、警告が無いことを表す形が2つになる。**`message` と警告の各要素は空にできない**
(空白だけも不可)——中身の無い説明は、読み手にとって説明が無いのと同じである。

### ツールエラーコード

`error` の `code` は次の8つで閉じている。

- `TOOL_INDEX_OUT_OF_RANGE`: 範囲外の位置を指した。
- `TOOL_INVALID_ARGUMENT`: 引数の値が不正。
- `TOOL_INVALID_HANDLE`: ハンドルが不正。
- `TOOL_CONFIRM_REQUIRED`: 危険操作の確認が無い。
- `TOOL_NOT_APPLICABLE`: 現在の状態・提供範囲で適用できない。理由を説明に含める。
- `TOOL_OPERATION_FAILED`: 実行に失敗した。例外の内容と、状態がどうなったかを説明に含める。
- `TOOL_RESPONSE_TOO_LARGE`: 応答が応答サイズ予算に収まらない。
- `TOOL_REQUEST_TOO_LARGE`: 要求が要求サイズ予算に収まらない。

### 応答サイズ予算の分け方

[応答サイズ予算](pmx-editor-mcp-architecture.md#応答サイズ予算の設定)は**本文**の文字数の上限で、
その内訳は**値の枠**と**警告の枠**の2つとする。本文とは、下記の結果のテキストから接続先を名乗る行を
除いた部分をいう。

- **警告の枠は2,000文字**。警告そのものに加えて、1件ごとに本文で伴う行の区切りと `警告: ` の
  接頭辞、そして切り詰めた旨の注記も、この枠の中に収める。
- **値の枠は予算から警告の枠を引いたもの**。
- 警告が枠に収まらないときは、**切り詰めた旨の注記を末尾へ置いた形が枠に収まるところまで前から
  採る**。警告を落とすのは、警告のために値を削るとツールの結果そのものが失われるからである。
- **値が値の枠に収まらないときは**[応答が大きすぎる](#ツールエラーコード)**として断る**。
  [一覧](#一覧)は件数を減らして返す道を持つので、そちらの規則が先に当たる。

### MCPクライアントへ返す結果

ブリッジが包みを結果へ写す。**包みそのものはクライアントへ見せない**。

- 結果は**テキスト1件**とし、接続先を名乗る行に続けて本文を置く。本文は、成功なら `value` の
  JSON表記、失敗なら `コード: メッセージ` とする。警告があれば本文の末尾へ `警告: ` で始まる行として
  足す。**画像を返すツールだけは、画像を先頭に置いてからそのテキストを続ける**。
  ドメインの失敗にも接続先の行を置くのは、呼び出しが成立して接続先の知らせを消費するからである
  ——ここで捨てると、接続先が変わった事実がどの応答にも現れなくなる。
- **公開する出力スキーマが述べるのは `value` の構造**である。包みを見せない以上、呼び出し側が
  受け取る形はそれだけになる。
- 失敗は結果の誤りの印を立てる。
- **本文が予算を超えていたら、本文を返さず `TOOL_RESPONSE_TOO_LARGE` の誤りにする**。値の枠と警告の
  枠はホストが守るので、ここで超えるのはホストが見落としたときだけである——最後の砦として置く。
- **包みとして読めない応答は、ホストの応答が契約から外れているものとして扱い、接続を捨てる**
  ——成否を持たない、成功なのに値が無い、失敗なのに誤りの内容が空、警告が空でない文字列の並びで
  ない、のいずれもここで落ちる。契約から外れた応答を返す相手とは、次の要求の応答も対応づけられない。

## 要求サイズ予算

要求の大きさの上限は**8,000,000バイト**とする。[IPCが運べる16MiB](pmx-editor-mcp-ipc.md)のおよそ
半分で、上限いっぱいを常用しないための余白をこの差が受け持つ。**設定では変えない**——受け取る側の
事情ではなく名前付きパイプが運べる量から決まる値で、設定にするとホストとブリッジで食い違って
受理できる件数がずれる。**応答と単位が違う**のは、限るものが違うからである——応答を限るのは
受け取るMCPクライアントで、数えるのは文字数になる。要求を限るのは名前付きパイプで、数えるのは
バイト数になる。

**ツールは、受け取った要求のUTF-8のバイト数がこの予算を超えていたら、実行せずに**
[要求が大きすぎる](#ツールエラーコード)**として断る**。説明には要求の大きさと予算を含める。状態は
[未変更](#編集の分類)である。判定はツールの処理の最初に置き、**[Undoの抑止](#undoの抑止)が
覚えた残留を戻しにいくより前**に済ませる——戻しにいくのはSDKを呼ぶことなので、先に断れば
SDKへ触れないまま状態が未変更であることが保てる。したがって**予算を超えた呼び出しでは残留を
戻しにいかず、戻したことの警告も載らない**。ホスト基盤が返す誤りはこの判定より先に立ち、
ツールでないメソッドはこの判定を持たない。

## 値の表現

ツールの引数と応答に現れる型のうち、**値そのものとしてJSONへ写す型**の写し方をここで定める。
役割を持つ型は載らない——それらは値として写さず、
[型役割仕様書](pmx-editor-mcp-type-roles.md)が定める役割ごとの扱いに従う。
**下記の型ごとの表に載るのは値として写せる型のすべて**で、載っていない型を値として写す道は無い。

### 表現の綴り

| 綴り | JSONの形 |
|---|---|
| `boolean` | 真偽 |
| `number` | 数値 |
| `text` | 文字列。`System.Version` は標準の表記とする |
| `base64` | バイト列をBase64で詰めた文字列 |
| `enum_name` | 列挙子名の文字列 |
| `number_array` | 成分を順に並べた数値の配列。並びは下記のとおり型で決まる |
| `color` | `[r, g, b]` または `[r, g, b, a]`。成分は0以上1以下の数値とする |
| `size` | `[幅, 高さ]` |
| `point` | `[x, y]` |
| `rectangle` | `[x, y, 幅, 高さ]` |
| `font` | `family`(書体名の文字列)・`size`(**ポイント**の数値)・`style`(列挙子名)を持つ組 |
| `brush` | 色の配列。ホストはその色の単色ブラシを組み立てる |
| `image` | Base64で詰めた画像。形式は[画像](#画像)が定める |
| `json` | 任意のJSON値。null・真偽・数値・文字列・配列・組を再帰的に組み合わせた形を許す |
| `null_value` | JSONの null |

`number_array` の並びは型で決まる。`PEPlugin.SDX.V2` は `[x, y]`、`PEPlugin.SDX.V3` と
`PEPlugin.Pmd.IPEVector3` と `SlimDX.Vector3` は `[x, y, z]`、`PEPlugin.SDX.V4` と
`PEPlugin.SDX.Q` と `PEPlugin.Pmd.IPEQuaternion` と `SlimDX.Quaternion` は `[x, y, z, w]`、
`PEPlugin.SDX.M` と `SlimDX.Matrix` は**行優先の16要素**とする。

成分を並べる型を**インターフェースで受け取るときは、それを実装する `PEPlugin.SDX` の公開クラスを
組み立てる**——`PEPlugin.Pmd.IPEVector3` は `PEPlugin.SDX.V3`、`PEPlugin.Pmd.IPEQuaternion` は
`PEPlugin.SDX.Q` である。組み立てる先を型ごとに一つに決めるのは、渡した先が実装型を見分けたときに
呼び出しごとに違う型が渡らないようにするため。

`color` は**送り出すときに4成分**とし、受け取るときは3成分と4成分のどちらも許す——3成分は不透明と
して読む。送り出す側を1つに決めるのは、同じ色が呼び出しごとに違う長さで返らないようにするため。

`font` の大きさは**ポイントで表す**。書体は自分の大きさを生成時に選んだ単位で持つので、単位を
そろえずに数値だけを渡すと、同じ見え方の書体が呼び出しごとに違う数値になる。

`enum_name` の綴りは、**組み合わせを許す列挙**では**当てはまる列挙子の名前を値の小さい順に並べ、
半角のコンマと空白の2文字で連ねた文字列**とする。組み合わせを許すかどうかは列挙の側が持つ。

`json` はホストがJSON値と行き来できる形で持つ。`null_value` は、出力スキーマの側でもnullの型として
書く。

**表せない値は、値を返さず**[適用できない](#ツールエラーコード)**として断る**——表せない旨を説明に
含める。何が表せないかは綴りごとに決まる。

- `number` と `number_array` と `color` は、**有限でない値**を表せない。
- `enum_name` は、**当てはまる列挙子の名前が無い値**を表せない。組み合わせを許す列挙で、どの列挙子
  にも当てはまらない部分が残る値もここに入る。
- `brush` は、**単色でないブラシ**を表せない。
- `json` は、**JSONの値へ写せない.NETのオブジェクト**と、**名前が文字列でない組**を表せない。

**受け取る値が綴りの形に合わなければ**[引数が不正](#ツールエラーコード)**として断る**。形に合うとは、
綴りが求めるJSONの種類であり、かつ次を満たすことをいう。

- `number` は**有限**で、整数で持つ綴りでは**端数を持たず**、その綴りが**持てる範囲**に収まる。
  単精度では、その綴りへ丸めた結果が有限であればよい——丸めで届く値まで受けないと、送り出した
  端の値をそのまま返せなくなる。
- `number_array`・`size`・`point`・`rectangle` は、その綴りが**求める数だけ成分を並べる**。
- `color` は成分を**3つか4つ**並べ、どの成分も**0以上1以下**である。
- `enum_name` は**当てはまる列挙子の名前**であり、名前を並べた綴りは**組み合わせを許す列挙**にだけ
  渡せる。
- `text` のうち版は、**標準の表記**である。
- `base64` は**Base64として解ける**。
- `font` は `family`・`size`・`style` だけを持ち、書体名は**導入されている**もの、大きさは
  **0より大きい**もので、その書体名と大きさとスタイルの**組み合わせで書体を組み立てられる**。
- `brush` は `color` と同じ形である。
- `image` は[画像](#画像)が定める形である。
- `json` は、入れ子の隅までJSONの値の形をしていて、**組の名前が文字列**である。

**`null` を受け取れるのは、値を持たないことがその型で表せる綴りだけ**とする——`nullable_` で包んだ
綴りと、値を参照で持つ型の綴りである。値そのものとして持つ型(数値・真偽・列挙・大きさ・位置・矩形・
色と、`SlimDX` の成分を並べる型)は受け取れない。この許否は、[スキーマ正本](#スキーマ正本)では
項目の `nullable` が持つ。**書き出す向きが `null` を
載せうる綴りと同じ範囲になる**ので、載せた応答をそのまま引数へ返せる。

**綴りが内側に持つ値には、その値の綴りの条がそのまま働く。** `font` が持つ大きさは数値、書体の
スタイルは列挙子名、`json` が持つ数値も数値なので、上の条がそれぞれに掛かる。要素を並べる形と
`nullable_` が包む要素も同じである。

### 画像

`image` の綴りが指す画像は、次のとおりやり取りする。

- 送り出す画像は**PNG**とする。**長辺が `maxLongSide` を超えるときは、縦横比を保って縮める**。
  長辺をその値へそろえ、短辺は比で求めて四捨五入し、1を下回らせない。縮めたときは、元の大きさと
  縮めた後の大きさを警告に載せる。
- `maxLongSide` は**既定512・最小256・最大2048**とする。画像はほかの値より桁違いに大きくなりうるので、
  量を大きさで抑える。既定を小さめに置くのは、受け取る側が画像をどう数えるかが分かっていない
  からである。**それでも最小の256を既定にしないのは、内容を判別できる大きさを既定のまま保つため**で、
  足りなければ呼び出す側が `maxLongSide` で最大まで引き上げられる。
- 受け取る画像は**PNGかBMP**に限り、辺は**4096まで**とする。ホストは32bitのARGBへ直してから使う。
  Base64として読めないもの・画像として読めないもの・形式が違うもの・辺が上限を超えるものは、いずれも
  [引数が不正](#ツールエラーコード)として扱う。

**受入条件**: 送り出した画像に、その時点のビューに見えている内容が描かれていること。**画像を返す
ツールごとに確かめる**。あわせて、既定の `maxLongSide` で送り出した画像が、MCPクライアントの側で
大きすぎるものとして扱われないこと——扱われるなら既定が大きすぎるので、この文書の既定を見直す。

### 包む型

**一列に並ぶ**配列と `System.Collections.Generic.IList<1>` は、要素の表現を `array_of_` で包む。
ただし**一列に並ぶバイトは `base64`** とする。**多次元の配列は値として写さない**——`base64` でも
`array_of_` でも各次元の長さが失われるので、どちらへ倒しても元の形へ戻せない。
`System.Nullable<1>` は、要素の表現を `nullable_` で包む。

**要素の表現が決まらない並びは、その並びも値として写さない。** 空の並びを写せてしまうと、要素が
1つでも入った同じ並びは写せない、という食い違いが起きる。

### 表の形

行は**2列**とし、型の欄は綴りを `` ` `` で囲む。表現の欄は、綴りが1つに決まる型ではその綴りを同じく
囲み、要素の表現を包む型では囲まない——囲んだ綴りだけを表現として読むので、包む型に綴りを書けば
その1つに決めたことになる。同じ型は二度現れない。

### 表の検査

値の表現の照合が、次を検査する。

- 表の型が、**値として写せる型と過不足なく一致すること**。載せ落とした型も、値として写せない型を
  足したのも、ここで落ちる。
- 綴りが1つに決まる型の表現が、**規則が導く綴りと一致すること**。
- **要素の表現を包む型に綴りが書かれていないこと**。

## 編集の分類

分類が付くのは**ツールの呼び出し**で、ツールそのものではない。**対象の指し方で作用の仕方が変わる
ツールは、指し方ごとに別の分類に当たる**——いまの状態を複製して反映する指し方と、実体を受け取って
直に触る指し方とでは、確定させる呼び出しが別のものになるからである。

エディタの状態か外部へ作用する呼び出しは、次の3つのどれか1つに当たる。**上から順に見て、最初に
当たった1つ**とする。

- **複製編集型**: いまの状態を複製して変え、まとめて反映するもの。
- **直接変更型**: 上に当たらないもののうち、モデルのデータ・長寿命のオブジェクト・ファイルへ直に
  作用するもの。
- **表示・セッション型**: 上のどちらにも当たらないもの。表示と設定とセッションだけを動かし、
  モデルのデータにも長寿命のオブジェクトにもファイルにも作用しない。

どちらへも作用しない呼び出しは**読み取り**とし、上の3つのどれにも当たらない。分類の値はこの
読み取りを合わせた4つで閉じている。機械可読の正本では、複製編集型を `duplicateEdit`・直接変更型を
`directChange`・表示・セッション型を `viewSession`・読み取りを `read` と書く。

どの分類も、処理の全体を**ひとつながりのUIスレッドの呼び出しの中で**行う。途中にエディタの手動の
操作が割り込まない。

**反映を確定させる呼び出し**は分類で決まる。複製編集型はまとめて反映する呼び出し、直接変更型は
そのSDK呼び出しの正常な返却、表示・セッション型は同じくその呼び出しの返却である。失敗したときに
エディタの状態がどうなっているかは、その呼び出しを境にして決まる。

| 失敗した位置 | 状態 | 呼び名 | 返し方 |
|---|---|---|---|
| 確定させる呼び出しへ入る前 | 変わっていない | 未変更 | 誤り |
| 確定させる呼び出しそのもの | 変わったかどうか分からない | 結果不明 | 誤り。その旨を本文へ含める |
| 確定した後 | 変わっている | 変更済み | 警告を添えた成功 |

**確定した後に失敗しうるのは複製編集型だけ**である。反映のあとに表示を更新する段があり、そこが
失敗しても反映は取り消せない。ほかの2つは、確定させる呼び出しが返ったところで終わる。

**結果を受け取れないまま呼び出しが終わったときの状態は、要求をホストへ送る前か後かで決まる**。
送る前に終わったもの——待ち行列・接続の確立・ハンドシェイクの途中——は変わっていない。送った後に
終わったもの——処理タイムアウト・送信の後のキャンセル・接続の切断——は変わったかどうか分からないので、
読み取りのツールで確かめる。

## 対象の集合

集合を対象とするツールは、**1件ではなく集合**を受け取る。指し方は次の4つで、**2つ以上を同時に
持つことも、1つも持たないこともできない**。

- `indices`: 位置の整数の配列。**位置は0以上で、対象のリストの件数より小さい**。
- `range`: `start`(最小0)と `count`(最小1)の組。
- `all`: 真。対象のリストの全要素を指す。
- `handles`: [ハンドル](#ハンドル)の配列。ハンドルが指す対象——まだリストへ加えていない生成物や、
  リストの外で生きる長寿命のオブジェクト——を指す。

`range` の項目名を[一覧](#一覧)の `offset`・`limit` と分けるのは、指すものが違うからである
——こちらはリストの位置、あちらは解決した集合の位置を指す。

**ここが定めるのは1つの集合の指し方である**。1つの要求が2つ以上の集合を指すこともあり、そのときは
集合ごとにこの規則が働く。**項目名は指す対象ごとに分ける**ので、どの項目がどの集合のものかは名前で
決まる——同時に持てないのは同じ集合を指す指し方どうしであって、別の集合を指す項目とは重ならない。
位置でもハンドルでも指せない対象を持つ集合は、その指し方を各ツールが自分の仕様で定める。その場合も
**空にできないこと・同じものを二度以上指せないこと・要求に現れた順で解けること**は同じく守る。

どの指し方を受け付けるかはツールごとに決まる。**その配列が空だと対象が決まらない配列は、空に
できない**——この節では `indices` と `handles` がこれに当たり、空の配列は引数が不正として断る。
対象を指す働きを持つほかの配列にも同じことが当てはまる。長さが対象の件数に従う配列(要素ごとの
値・引数の並び)には課さない。対象が0件なら空が正しいからである。

**同じ要素を二度以上指す指定も断る**。取り除いて先へ進めると、指定した配列の長さと要素ごとの値の
並びの長さが食い違う。ハンドルの重複では、1件目が消費された時点で2件目が必ず失敗する。要求の
誤りとして、解決の前に返す。

**解決した集合の順序**は、並びのある指し方(`indices`・`handles`)では要求に現れた順、並びを
持たない指し方(`range`・`all`)ではリストの位置の昇順とする。要素ごとの値・引数の並びは、この順で
対象へ対応づく。[一覧](#一覧)の `offset` と `limit` は、解決した集合に対して働く。

**断り方は、何が誤っているかで決まる**。

- **指し方そのものの誤り**は[引数が不正](#ツールエラーコード)とする。2つ以上・1つも無い・その
  ツールが受け付けない指し方・空の配列・同じ要素を二度以上指すこと・`range` の `start` が0を
  下回るか `count` が1を下回ることが、これに当たる。
- **位置がリストの外にある**ときは[範囲外の位置](#ツールエラーコード)とする。`indices` の位置が
  0を下回るときも、リストの件数以上のときも、`range` の指す末尾がリストを越えるときも同じである。
- **`handles` に使えないハンドルがある**ときは[ハンドルが不正](#ツールエラーコード)とする。

### 部分適用をしない

**検証は適用の前にすべて済ませ、途中まで適用した状態を残さない**。対象の解決——位置が範囲の中に
あること、ハンドルが使えること——と、値・引数の全項目の検証を、対象の全件について先に行う。
**1件でも不正なら何も変えずに断り**、状態は[未変更](#編集の分類)とする。値・引数の全項目の検証と
は、**項目の名前が知られたものであること・値がその項目の取りうる範囲に収まること・参照の位置が
リストの中にあること・nullを許さない項目にnullが来ていないこと**を見ることをいう。

- 全件へ同じ値・引数を使う指定は、**対象の件数によらず1度は全項目を検証する**。対象がたまたま
  0件でも省かない——要求の値が不正であることは対象の件数と関わりなく決まるので、空のときだけ
  通るのは一貫しない。
- 要素ごとの値・引数の並びは対象と同じ長さなので、対象0件では検証も0回になる。
- **直接変更型の呼び出しにも同じく課す**。複製を介さないので、適用より前に済ませない限り途中まで
  適用された状態が残る。

## 一覧

一覧を返すツールは、**どこから何件か**を受け取り、**総数・切り出した並び・続きの位置**を返す。

- 受け取るのは `offset`(既定0・最小0)と `limit`(最小1)。負の数・整数でないもの・範囲の外は
  [引数が不正](#ツールエラーコード)として断る。`limit` の既定と最大は、要素型によって1件あたりの
  大きさが違うので共通の値を持たず、**[想定文字数](#想定文字数)から
  [要素型ごとに逆算する](#一覧の件数)**。
- 返すのは `total`(切り出す前の総数)・`items`(切り出した並び)・`nextOffset`(続きがあるときだけ)。
  **`items` の要素は組とする**——[返す項目](#返す項目)で選べる単位がその中の項目だからである。
- **`offset` が `total` 以上のときは、空の `items` を正常として返す**。位置が末尾を越えていることは
  誤りではない。
- 組み立てた値が[値の枠](#応答サイズ予算の分け方)に収まらないときは、**収まる件数まで減らして
  返す**。枠に照らすのは `items` だけでなく、`total` と `nextOffset` を含む値の全体である。
  減らしたときは、減らす前に切り出せた件数と返した件数を警告に載せ、`nextOffset` は返した件数の
  ぶんだけ進める。**1件も返せないときは**[応答が大きすぎる](#ツールエラーコード)として断る。

[イベント](#イベント)の取り出しはこの規則の対象外とする。溜まったものを古い順に渡す形なので、
位置で区切らず、続きの位置も持たない。

## 返す項目

要素を返すツールは、**返す項目名の配列 `fields` を任意で受け取る**。一覧を返すかどうかに依らない。

- **省略したときは、読み取り可能な項目をすべて返す。**
- **指定できるのは読み取り可能な項目名だけ**とする。読み取り可能な項目に無い名前・空の配列・同じ
  名前の重複は、いずれも[引数が不正](#ツールエラーコード)として断る。空の配列を断るのは、項目を
  1つも持たない要素を返しても呼び出し側に何も伝わらないうえ、空を全項目の意味に取れば省略と同じ
  ことを二通りに綴れてしまうためである。
- **各ツールが常に返すと定めた合成の項目は、この選び方の外に置く。** 指定できず、指定の有無に
  依らず返る。ホストが組み立てて載せるもので、読み取り可能な項目には入らない。
- **返す項目の並びは、指定の並びに依らない。** 合成の項目を先に、選んだ項目をその後に置く。
  どちらの側も、その中の並びは**そのツールの出力スキーマが定める並び**に従う。同じ要素が、頼み方
  の違いだけで違う並びの組にならないようにする。

## 危険操作

取り返しの付かない呼び出しは、**呼び出す側の確認を求める**。確認は共通引数 `confirm` を真に
して示し、**無ければ実行せずに**[確認が要る](#ツールエラーコード)として断る。確認を要するのは
次の3つとする。

- **エディタ終了**: エディタそのものを終わらせるもの。
- **上書き保存**: ファイルへ書き込むもの。上書きになるかどうかは問わない——書き込む先が既に
  あるかは、呼ぶ前には分からない。
- **モデル初期化**: 開いているPMXの中身を一度に空にするもの。別の内容を読み込んで置き換えるものは、
  空にするのではないので当たらない。

どのシグネチャが当たるかは名前で決める。意味の近い別のメンバーを巻き込まないよう、**名前だけで
決めてよいものと、宣言型と組で名指しするもの**を分ける。

- エディタ終了は、`PEPlugin.Form.IPEFormConnector` の `Close`。
- 上書き保存は、**メンバー名が `Save` で始まるものと `ToFile`**。提供対象には、この名前で
  ファイルへ書き込まないメンバーも、この名前以外でファイルへ書き込むメンバーも無い。
- モデル初期化は、`PEPlugin.Form.IPEFormConnector` の `InitializePMD` と `InitializePMX`、および
  `PEPlugin.Pmx.IPXPmx` の `Clear`。名前が同じでも、ほかの型の `Clear` は当たらない。

`PEPlugin.Pmx.IPXPmx` の `Clear` だけは、**呼ぶ対象で要否が分かれる**。開いているPMXを対象に
呼ぶときは確認を要し、対象を指定して呼ぶときは要さない——後者が空にするのはエディタが開いている
ものではなく、メモリの上に作った生成物だからである。

[能力台帳](pmx-editor-mcp-capability-ledger.md)は同じシグネチャを備考へ記す。上の決め方が導くものと
台帳が記すものが、集合としても種別としても食い違わないことを検査する。**検査はシグネチャ単位で
行う**ので、呼ぶ対象による上の分かれ方は検査に現れない。

## Undoの抑止

編集をエディタのUndoへ積まないようにできる。積むかどうかはエディタの側の記録なので、止めたまま
放置すると、以後の編集をどれも戻せなくなる。そこで次を規則とする。

- 止めたら、**編集の成否や例外によらず必ず戻す**。止める呼び出しそのものが失敗したときは、
  止まっていないものとして扱い、戻さない。
- 戻せなかったときは、**その場で1度だけやり直す**。
- それでも戻らなかったときは、**戻せていないことを覚える**。覚えるのは接続をまたぐ1つの状態と
  する——止まっているのはエディタの側なので、接続が切れても直らない。後から戻せたときに、覚えた
  ことを消す。

**[複製編集型](#編集の分類)がまとめて反映するのは、1呼び出しにつき1回**とする。抑止はその呼び出しの
中の登録を止めるだけで、**呼び出しをまたぐ編集を1つへまとめる手段は持たない**。

**受入条件**: まとめて反映する1回の呼び出しが、実機のエディタの元に戻す操作1回で呼び出し前の状態へ
戻ること。**対象が何件でも1回で戻る**ことまでを含む。

**止めることを頼めるのは[複製編集型](#編集の分類)の呼び出しだけ**とし、ほかの分類が頼んだら
[引数が不正](#ツールエラーコード)として断る。止めても効くのはまとめて反映するときのUndoの登録に
限られるので、その反映を持たない呼び出しでは頼んでも何も起きない。

**戻せていないことを覚えている間は戻しにいく**。試みるのは、**ツールの呼び出しの冒頭・接続が
終わるときの後始末・新しい接続のハンドシェイクの直後**の3つとする。戻せたら、以後の最初の応答に
警告で知らせる。呼び出しの冒頭で戻せなかったときの扱いは分類で分かれる。

- **複製編集型と直接変更型は、実行せずに**[実行に失敗した](#ツールエラーコード)**として断る**。
  止まったままの状態でエディタの側を変えると、その変更をどれも戻せなくなる。断るので状態は
  [未変更](#編集の分類)である。
- **表示・セッション型と読み取りは実行し、応答へ警告を添える**。エディタの側を変えないので、
  止まったままでも失うものが無い。

**戻せていないことを覚えたら、それを作った呼び出しの応答にも載せる**。成功なら警告として、失敗なら
誤りの説明へ足す。覚えたことが呼び出し側へ伝わらないと、次の編集を戻せない理由が分からない。

## ハンドル

PMXの状態の外で生きるSDKのオブジェクト——UIモデル・イベントコネクタ・イベントリスナ・テキスト
コントロール・ビルダの生成物——は、**ホストが台帳で保持し、ツールはハンドルIDで参照する**。実体を
やり取りせずIDで指すので、ツールの引数と応答は値だけで書ける。

- **IDは接続ごとの正整数**で、1から順に増える。使い回さない。
- **所有者はホスト**。ツールは実体を受け取らず、台帳を通してだけ触る。
- ハンドルは**生成に関与したハンドル**(依存元。複数でもよい)を覚える。UIモデルのイベント
  リスナが、生成元のUIモデルと引数に取るイベントコネクタの両方に依存するような場合である。
- **解放は子から依存元の順**で行う。依存元を解放すると、それに依存するものを先に解放して
  失効させる——先に依存元を手放すと、子の解放が拠り所を失う。
- **解放の仕方は型ごとに違う**ので、発行するときに決めて台帳が覚える。
- 台帳が知らないID・解放済みのID・**期待する型と違う**ハンドルは、いずれも使えないハンドルとして
  同じに扱う。どれであるかを返すと、台帳の中身を呼び出し側へ教えることになる。二度目の解放も
  ここで落ちる。
- **解放が例外になっても失効させ、後続の解放は続ける**。SDKの側がどうなったかは分からないので、
  そのハンドルは失敗したものとして呼び出し側へ知らせる。途中で止めると、解放できたはずのハンドルが
  台帳に残る。
- **まとめて解放できる**。接続が終わるときに、残っているハンドルを同じ順序の規則で解放し、**台帳を
  閉じる**。閉じた台帳は発行を受け付けない——解放を走らせている間に発行できると、そのハンドルが
  誰にも解放されないまま残る。
- **結果を破棄する呼び出しが発行したハンドルは、破棄するときに解放して失効させる**。破棄するのは
  [処理が上限の時間を超えたとき・処理が例外で終わったとき・応答を組み立てられないか大きすぎる
  とき](pmx-editor-mcp-ipc.md#エラーと切断の規則)である。同じ順序の規則で解放し、台帳は閉じない。
  呼び出し側へ届かないIDを残すと、誰も解放できないまま接続の終わりまで居座る。

## イベント

購読しているイベントは**取りに来たぶんだけ渡す**。押し出す通知は持たない——ツールの呼び出しと同じ
向きだけでやり取りするので、受け取り側は自分の都合で読める。

- イベントは**接続ごとに溜める**。溜められるのは1000件までで、超えたら**古いものから捨てる**。
- 各イベントは、**接続の中で1から増える連番** `seq`・イベント種別の識別子 `type`・そのイベントを
  購読しているリスナのハンドルID `sourceHandle`・イベント固有の値 `payload` を持つ。
- 取り出しは**古い順**に、指定した件数まで。件数は `limit` で受け取り、既定100・最小1・最大1000と
  する。負の数・整数でないもの・範囲の外は[引数が不正](#ツールエラーコード)として断る。
- 取り出しの結果は、取り出した並び `events` と、**捨てた件数** `dropped`——前回の取り出しから今回
  までに溢れて捨てたぶんで、返したところで0へ戻す——と、**取り出した後に残っている件数**
  `remaining` を持つ。
- 受け取り側は、**連番の欠番と捨てた件数**で取りこぼしを知る。どちらも無ければ、そのイベントの列は
  途切れていない。

**受入条件**: 実機のエディタのUIを操作してイベントを起こしたとき、取り出しが当該の `type` を返し、
その `sourceHandle` が購読しているリスナのハンドルIDと一致すること。**リスナの型ごとに確かめる**
——型が違えば発火する経路も違うので、1つで代表させられない。

## 割当

共通契約が受け持つシグネチャは、次の3つのいずれかへ割り当てる。どれかを1つだけ持ち、対象名を伴う。

- `tool`(ツールへの束縛): 対象名はツールの名前。公開の解放・破棄のように、ツールが受け持つもの。
- `commonArg`(共通引数への割当): 対象名は共通引数の名前。Undoの抑止のように、ツールの引数として
  現れるもの。
- `internalFlow`(内部フローへの割当): 対象名は内部フローの名前。ホストが自分で呼ぶもの。

## 内部フロー

内部フローの名前は次の4つで閉じている。**`internalFlow` の対象名になるのは前の3つ**で、
`releaseHandle` はツールが受け持つので `tool` の側に現れる。

- `duplicateEdit`(複製編集): 現在のPMXを複製し、編集し、反映する流れ。
- `stateRead`(状態取得): 現在のPMXを複製して読む流れ。
- `connect`(接続初期化): ホストの起動時に、接続点と常駐アクセスオブジェクトを得て、それらを使う前に
  要る初期化を済ませる流れ。Cプラグイン連携の入口である接続の根の複製は一次資料が利用非推奨として
  おり、ホストは起動時に一度だけ得て常駐期間中保持し、エディタの終了時に破棄する。
- `releaseHandle`(ハンドル解放): ハンドルを解放し、台帳から失効させる流れ。解放は常にツールを
  通して行い、台帳の失効と依存する子の先行解放に連動させるので、ホストが自分で呼ぶ流れにはしない。

## 束縛先スロット

シグネチャの**戻り値・入力引数・レシーバー**をそれぞれ何へ束縛するかを表す名前。次の10個で閉じている。

- `pmxClone`(PMX複製): 現在のPMXの複製。
- `updateKind`(更新種別): 反映する対象の種別。
- `updateIndices`(更新インデックス): 反映する対象の位置。
- `undoLock`(Undoロックフラグ): 反映のときにUndoを積むかどうか。
- `runArgsClone`(RunArgs複製): 接続の根の複製。常駐するコネクタとモジュールパスはここから取る。
- `modulePath`(モジュールパス): 接続の根の複製を求めるときに渡すホストプラグイン自身の位置。
- `residentObject`(常駐アクセスオブジェクト): ホストが常駐期間中保持するコネクタ。
- `targetHandle`(対象ハンドル): 解放・破棄の対象。
- `owningObject`(所有側オブジェクト): 呼び出しを受けるコネクタ・親オブジェクト。
- `injectedConnector`(自動注入コネクタ): `PXCPlugin.IPXCPluginConnector` 型の引数への常駐コネクタの
  束縛。この型の引数はツールのスキーマへ公開せず、ホストが常駐保持するコネクタを注入する。

**割当ごとに使えるスロットが決まる。** `internalFlow` はその内部フローのスロット、`tool` は
ハンドル解放のスロット、`commonArg` は流れに固有のスロットを持たない。加えて `owningObject` と
`injectedConnector` はどの割当でも使える。流れごとのスロットは次のとおり。

| 流れ | 割当 | 使えるスロット |
|---|---|---|
| 複製編集 | `internalFlow` の `duplicateEdit` | `pmxClone`・`updateKind`・`updateIndices`・`undoLock` |
| 状態取得 | `internalFlow` の `stateRead` | `pmxClone` |
| 接続初期化 | `internalFlow` の `connect` | `runArgsClone`・`modulePath`・`residentObject` |
| ハンドル解放 | `tool` | `targetHandle` |

**どの束縛もシグネチャから機械で決まり、書き手が選べない**。決め方を下に示す。戻り値が
`System.Void` のシグネチャは戻り値の束縛を持たず、静的なシグネチャはレシーバーの束縛を持たない。
**解放・破棄**とは、メンバー名が `Dispose` であるか `Release` で始まるものをいう。

- **戻り値**: [接続の根](pmx-editor-mcp-role-types.md)なら `runArgsClone`。ほかの
  [コネクタ型](pmx-editor-mcp-type-roles.md)なら `residentObject`。`PEPlugin.Pmx.IPXPmx` なら
  `pmxClone`。
- **入力引数**: `PXCPlugin.IPXCPluginConnector` なら `injectedConnector`。`PEPlugin.Pmx.IPXPmx` なら
  `pmxClone`。`PEPlugin.Pmx.PmxUpdateObject` なら `updateKind`。`System.Int32` かその配列なら
  `updateIndices`。`System.Boolean` なら `undoLock`。`System.String` で、戻り値が接続の根なら
  `modulePath`。[ハンドル操作型](pmx-editor-mcp-type-roles.md)なら `targetHandle`。
- **レシーバー**: 引数を持たない解放・破棄なら `targetHandle`。ほかは `owningObject`。

**どのスロットとも決まらない引数・戻り値が1件でもあれば、照合は判定を出さずに止まる**——決め方が
その形を覆えていないので、機械の判断として通すか落とすかを決められない。**入力でない引数**
(`out`・`ref`)もここに当たる——スロットはホストが渡す値と受け取る値を表すもので、呼び出しの側へ
書き戻される引数の置き場を持たない。

## 正本の形

### 共通契約割当の正本

`assignments` を項目に持つ組とする。各項目は次を持つ。

- `signatureKey`: 公開API列挙の行キー。**項目はシグネチャ単位**とする——同名のオーバーロードは
  束縛が異なるので、宣言型とメンバー名だけでは分けられない。
- `assignment`: [割当](#割当)の3つのいずれか。
- `target`: 割当の対象名。`internalFlow` では[内部フロー](#内部フロー)のうち対象名になる3つの
  いずれか、`tool` では
  小文字で始まり小文字と数字と下線だけからなる語、`commonArg` では小文字で始まり英数字だけからなる
  語とする——ツールの名前と引数の名前がそれぞれその形だからである。
- `slotBinding`: 戻り値・入力引数・レシーバーの[束縛](#束縛先スロット)。`return` と `receiver` は
  持つときだけ書き、`parameters` は引数の名前からスロットを引く組とする(引数を持たない
  シグネチャでは空の組)。値は機械で決まるので、[検査](#検査)が導いた束縛と突き合わせる。
- `basis`: そう割り当てた根拠の一文。

項目は行キーの序数の昇順に並べ、同じ行キーは二度現れない。**母集合は提供対象のシグネチャに限る**。
接続の経路そのもの——ホストが接続の根から常駐アクセスオブジェクトへ辿る取得プロパティ——は
[能力台帳](pmx-editor-mcp-capability-ledger.md)が非対応とするので提供対象に入らず、この表は
持たない。辿り方は
[型役割仕様書](pmx-editor-mcp-type-roles.md)の接続の経路が正本である。

### 能力対応表

[能力台帳](pmx-editor-mcp-capability-ledger.md)の提供能力を、**提供対象のシグネチャ単位の行**へ
展開した表とし、[能力対応表の正本](pmx-editor-mcp-tool-map.json)を値の正本とする。`rows` を項目に
持つ組とし、母集合は提供対象のシグネチャの全体、行は行キーの序数の昇順に並べ、同じ行キーは二度
現れない。

各行は次を持つ。

- `signatureKey`: 公開API列挙の行キー。
- `capabilityIds`: その行を出した提供能力のIDの配列。1件以上とし、同じIDを二度並べない
  ——**同じシグネチャを複数の能力が指すことがある**(基底型が宣言するメンバーを、複数の派生型の
  能力が同じく指す)。
- `rowKind`: **行の種別**。下記の5つのいずれか一つで、行はちょうど1つを持つ。
- `editKind`: [編集の分類](#編集の分類)の4値のいずれか一つ。**対象の指し方で分類が変わる行は、
  現在のPMX状態を対象とする呼び出しの分類**を書く。現在のPMX状態を対象にできない行——対象が
  未追加の生成物に限られるもの——は、その呼び出しの分類を書く。ほかの呼び出しの分類は対象から
  決まるので、行は持たない。
- `direction`: **操作の向き**。値を読み出す側が `read`、それ以外が `write` とする。**どちらかは
  シグネチャから決まる**——プロパティの取得側として現れるメンバーと、戻り値を持ち `out`・`ref` を
  取らず、名前が `Get`・`Is`・`Has`・`Can`・`Find`・`Search` のいずれかで始まるメソッドが `read`
  で、残りがすべて `write` である。
- `dangerKind`: [危険操作](#危険操作)に当たる行に必須。`shutdown`(エディタ終了)・
  `overwrite`(上書き保存)・`reset`(モデル初期化)のいずれか。当たらない行は持たない。
- `updateSpec`: [複製編集型](#編集の分類)の行に必須で、ほかの分類の行は持たない。次の2つを持つ。
  - `update`: 反映を一部に限るときの指定で、`PEPlugin.Pmx.PmxUpdateObject` の列挙子名とする。
    **全体を反映する行と、反映の範囲を引数で受け取る行は持たない**——後者はどの範囲になるかが
    呼び出しごとに変わるので、行では決まらない。どの位置を反映するかは呼び出しが解いた対象から
    決まるので、行は持たない。
  - `refresh`: 反映の後に呼ぶ表示更新の名前の配列。`model`(モデルの実体)・`list`(フォームの
    一覧)・`view`(描画)を重複なく並べる。呼ばない行は空の配列とする。
- `note`: 備考。台帳の契約注記の**本文をそのまま写したもの**で、注記を持つ能力から出た行に必須、
  ほかの行では任意。複数の能力から出た行は、能力IDの昇順に句点で連ねる。同じ本文は一度だけ書く
  ——注記を持つ能力の多くが同じ制約を述べるので、畳まないと同じ一文を並べることになる。
- `basis`: `editKind` と `updateSpec` をそう決めた根拠の一文。この2つは書き手が判じるもので、
  機械が見分けられるのは欠落と多重分類までなので、判断を後から追える形にする。ほかの項目は
  シグネチャと台帳と写像規則から決まるので、根拠を持たない。

### 行の種別

`rowKind` は次の5つとし、行ごとに必要な項目が変わる。

- `composed`(合成ツール): SDKのメンバーへの1対1の中継ではないツールの行。`tool`(ツール名)と
  `postcondition` を持つ。
- `commonContract`(共通契約割当行): 個別のツールを持たず、共通契約の側が受け持つ行。
  `assignment`・`target`・`slotBinding` を[共通契約割当の正本](#共通契約割当の正本)と同じ形で
  持ち、`postcondition` は持たない。
- `eventBranch`(イベント行): [イベント](#イベント)の取り出しが返す `type` の分岐に当たる行。
  `eventType`(その分岐の `type` の値)を持ち、`postcondition` は持たない。
- `schemaEmbedded`(スキーマ埋め込み行): 独立したツールを持たず、ほかのツールの入出力スキーマか
  イベントの分岐へ埋め込まれる行。`embeddedIn`(埋め込み先の名前の配列。1件以上で、同じ名前を
  二度並べない。**ツールの名前か、イベントの `type` の値**)を持ち、`postcondition` は持たない。
  **配列にするのは、1つの項目が取得のツールと更新のツールの両方へ埋め込まれるため**である。
  ツールへ埋め込まれる行では、読み取り可能な項目が取得の側を、書き込み可能な項目が更新の側を、
  それぞれ持つ。
- `directDispatch`(直接ディスパッチ行): 上のいずれでもなく、独立したツールを持ってSDKのメンバー
  へ中継する行。`tool`(ツール名)と `postcondition` を持つ。

### 事後条件

`postcondition` は、その行の呼び出しが**外から観測できる効果**をどう確かめるかを述べた**判定の
配列**とする。1つの行が複数の効果を持つときは複数並べ、**すべて成り立つこと**を合格とする。
各判定は次を持つ。

- `effectType` と `effectKey`: その判定がどの効果に当たるかの識別子。`effectType` は
  `fileWritten`・`handleConsumed`・`handleCascaded`・`handleCreated`・`countChanged`・
  `stateWritten`・`observableChange`・`valueRead`・`none` の9つのいずれか。`effectKey` はその
  効果を行の中で一意にする文字列で、引数名・取得メンバー名・コレクション名・発行するハンドルの
  型名・ツールの名前・[参照元](#参照元)の射影の文字列のいずれか、または効果が1行に1つしか無い
  種別では空文字とする。**この組は配列の中で二度現れない。**
- `kind`: `readback`(読み取りのツールで読み戻して比べる)・`file`(ファイルの生成)・
  `handle`(ハンドルの状態の変化)・`callLogOnly`(外から観測できる効果を持たず、ディスパッチの
  記録だけを合格とする)の4つのいずれか。
- `observerTool` と `observerArgs`: `readback` と `handle` で必須。観測に使うツールの名前と、
  その引数の束縛とする。**束縛は式を持たず、観測ツールの引数名から[参照元](#参照元)を引く組
  だけ**とする——同じ参照元を2つの引数へ束縛できるので、引く向きは引数名の側からとする。ただし
  `comparison` が `anyChanged` の判定では**書かない**——何を観測するかは行ごとに書かず検査の側が
  決めるためで、書いてあれば形が違うものとして落ちる。
- `valuePath`: `readback` で必須(`comparison` が `anyChanged` の判定では書かない)。比べる値の
  位置を、**観測ツールの応答の値そのもの(空文字)・値の直下の項目名1つ・一覧の応答からの配列
  射影 `items[].<項目名>`** のいずれかで指す。これより深い入れ子は指せない——指せない深さの値を
  比べる必要が出たら、その値を直に返す観測ツールを選ぶ。
- `comparison`: `equals`(`expected` と等しい)・`exists`(在る)・
  `invalidated`(以後その値をハンドルとして使う呼び出しが[ハンドルが不正](#ツールエラーコード)に
  なる)・`deltaEquals`(呼ぶ前の値との差が `expected` に等しい)・`anyChanged`(検査の側が決めて観測した
  値のうち、少なくとも1つが呼ぶ前と違う)の5つのいずれか。
- `expected`: `equals` と `deltaEquals` で必須。**JSONのリテラル**か[参照元](#参照元)1つの
  いずれかとし、**演算も合成も持たない**。`deltaEquals` のリテラルは**数値**とする。
  期待と観測の形が違うときの突き合わせは次で閉じる——**期待が単一の値で観測が配列なら、配列の
  全要素をその値と比べる**。期待が配列なら、**同じ長さ・同じ順序で要素ごとに比べる**。どちらも
  新しい値を作らないので、演算も合成も持たない規則のままである。
- `setup`: **`observableChange` と `valueRead` の判定が持ち、ほかの効果種別は持たない**。既知の
  状態を作ってから確かめるのがこの2つだからである。[用意の操作](#用意の操作)の列とし、**並びも
  `effectType` ごとに決まる**ので、判定ごとに組むものではない。

`kind` が `file` のとき、確かめるパスは `effectKey` が指す引数から取る——別の指定を持たない。
指すのは**SDKのシグネチャの引数**とし、ここだけ `effectKey` が名前の札ではなく束縛になる。したがって
**この判定の `effectKey` は空にできない**——効果が1行に1つでも、指す引数が要る。

#### 参照元

束縛と `expected` が指せるのは、次の4つの名前空間だけとする。接頭辞で見分け、式も演算も持たない。

- `arg:<引数名>` — その行へ渡した**ツールが直に受け取る引数**。**組の配列を受け取る引数に限り**、
  内側を指す射影を2つだけ許す——`arg:<引数名>[].<項目名>`(各組の当該項目を並べた配列)と
  `arg:<引数名>[].<配列項目名>[]`(各組の当該配列を平らにした配列)。
- `sdkArg:<引数名>` — **SDKのシグネチャの引数**。集合を対象とするツールでは引数の組の内側に
  入るので、直に受け取る引数とは別の名前空間にする——**同じ名前が両方に現れうる**ためである。
- `result:<valuePath>` — その行の応答から取った値。書式は `valuePath` と同じ。
- `setupOut:<名前>` — [用意の操作](#用意の操作)が出した値。指せるのは**同じ判定の操作が出した
  名前**に限り、**操作の引数が指せるのはその操作より前が出した名前**とする——列は順に実行するので、
  後で出す名前は先の操作から引けない。

**ツールの引数名・値の項目名・出した値の名前は、いずれも小文字で始まり英数字だけからなる語**と
する——要求と応答の項目がその形だからである。観測ツールの引数の名前も同じ形とする。**SDKの引数名
だけは識別子の形までとする**——名前を決めるのはSDKの側で、下線を含む名前が実在する。

#### 用意の操作

`setup` が並べられるのは、次の3つのタグの操作だけとする。自由な手順は持たない。
各操作は `out`(出した値の名前。出さないときは持たない)を持てる。**同じ名前を二度出さない**
——[参照元](#参照元)は名前で引くので、重なると指す先が決まらない。

- `initPmx` — 空のモデルへ初期化する。値を出さない。
- `addElement`(`elementType`) — その要素型を1件足す。要素型は
  [型役割仕様書](pmx-editor-mcp-type-roles.md)の要素名詞で指す。出す値は足した要素の位置。
- `callTool`(`toolName`・`args`) — ツールを1回呼ぶ。`args` の束縛は[参照元](#参照元)に加えて、
  **JSONのリテラル**と**型ごとに定めたサンプル値への参照**(`sample:<型名>` でその型の既定の値、
  `sample2:<型名>` で同じ型の2つ目の値。型名は公開API列挙の表記)を取れる。出す値は応答の値。

サンプル値が実際にどんな値になるかは、検査の側が持つ——ここで閉じるのは、`setup` がそれを
どう指すかまでである。

### スキーマ正本

すべてのツールの入出力の形を持つ表とし、[スキーマ正本](pmx-editor-mcp-tool-schemas.json)を値の
正本とする。`tools` を項目に持つ組とし、母集合は[能力対応表](#能力対応表)が `tool` を持つ行のツールの
全体、項目はツールの名前の昇順に並べ、同じ名前は二度現れない。

各項目は次を持つ。

- `tool`: ツールの名前。小文字で始まり、小文字と数字と下線だけからなる語とする。
- `branches`: **入力の呼び分け**の並び。1つのツールが同じ名前のまま複数の受け取り方を持つときに、
  その受け取り方ごとの入力を並べる。呼び分けを持たないツールも1件の並びとする。
- `output`: 応答が返す値の形。[項目](#項目)と同じ形を取るが、**`name` を持たない**——応答の値
  そのものだからである。値を返さないツールは `null_value` の綴りを持つ。
- `listing`: [一覧](#一覧)を返すツールだけが持つ組。`limitDefault` と `limitMaximum` に `limit` の
  既定と最大を持つ。どちらも**1以上の整数**とし、既定は最大を超えない。どちらも要素型ごとに逆算した
  値で、**[応答サイズ予算](#応答サイズ予算の分け方)から算出した値と一致する**。[イベント](#イベント)の
  取り出しは一覧の規則の対象外なので**この組と `payloads` は同じツールに並ばず**、`limit` の項目の
  側が持つ `default` と `bounds` がその値になる。
- `payloads`: [イベント](#イベント)の取り出しだけが持つ、`type` の分岐の並び。**1件以上**とし、
  各分岐は `type`(その分岐の値)と `members`(その分岐で `payload` が持つ[項目](#項目)の並び)を
  持ち、同じ `type` は二度現れない。**この項目を持つツールは表に1つだけ**とする。

`branches` の各分岐は次を持つ。

- `branch`: 分岐の名前。**小文字で始まり英数字だけからなる語**とし、同じツールの中で二度現れない。
- `selector`: 分岐を選ぶ項目の `name` と `value` の組。**値で分かれる呼び分けだけが持つ**。持たない
  分岐は、入力の項目の名前と形で分かれる。`name` はその分岐の入力に実在する項目を指し、`value` は
  **JSONのリテラル**とする。
- `inputs`: その分岐が受け取る[項目](#項目)の並び。
- `choices`: **同時には持てない項目のまとまり**の並び。各まとまりは `names`(項目の名前の並び。
  2件以上で、その分岐の入力に実在し、まとまりをまたいで二度現れない)と `required`(そのうち必ず
  1つを要るなら真、無くてもよいなら偽)を持つ。まとまりに入る項目は、要不要がまとまりの側で決まる
  ので**自分では `required` を持たない**。

#### 項目

`inputs`・`output`・`members` が並べる項目は、**形を次の3つのうち1つで表す**。ただし[イベント](#イベント)の
取り出しの応答が持つ `payload` は、形を `payloads` が `type` ごとに定めるので、3つのどれも持たない。

- `shape`: [値の表現](#値の表現)の綴り。**要素を並べる形は `element` が表すので、`array_of_` で
  包んだ綴りは使わない**(バイト列を詰めた `base64` は文字列なので使う)。`null` を許すかどうかは
  `nullable` が持つので、`nullable_` で包んだ綴りも使わない。
- `members`: 組の中の項目の並び。組を表す。
- `element`: 要素の項目1つ。**その項目を並べた配列**を表す。要素が組なら、この項目が `members` を
  持つ。要素の項目は **`name` を持たない**——配列の要素に名前は無いからである。

そのうえで、次を持つ。

- `name`: 項目の名前。**小文字で始まり英数字だけからなる語**とし、同じ並びの中で二度現れない。
- `origin`: その項目がどこから来たか。`sdkIn`・`sdkOut`・`sdkRef`(SDKのシグネチャの引数で、
  入力・出力・その両方のどれに現れるか)・`sdkReturn`(SDKの戻り値)・`hostInput`(ホストの側が
  決める入力——共通契約が定める引数・対象の集合の指し方・値や引数を運ぶ器)・`hostOutput`
  (ホストが組み立てて載せる応答の項目)のいずれか。[返す項目](#返す項目)が選び方の外に置くのは、
  `hostOutput` の項目である。
- `required`: **呼び出す側が渡す項目**が必須かどうか。`choices` のまとまりに入る項目は持たない。
  応答の項目・名前を持たない項目・`injected` の項目も持たない——選べないものに要不要は無い。
- `default`: 省略したときに使う値。持つ項目だけが書く。**JSONのリテラル**とし、演算も参照も持たない。
- `bounds`: 値の取りうる範囲。持つ項目だけが書く。**`minimum` と `maximum` の組**とし、どちらも数値で、
  **少なくとも一方を持ち**、両方を持つときは `minimum` が `maximum` を超えない。
- `nullable`: `null` を許すかどうか。**値を参照で持つ項目と、値を持たないことを許す型
  (`System.Nullable<1>`)を写す項目は既定で許す**。一次資料がその項目を許さないと述べていれば、
  そちらを採る。
- `source`: **SDKに由来する** `default` か `bounds` を持つ項目に必須で、その値の**転記元となる
  一次資料の記載**。書き写した値がどこから来たかを追える形にする。共通契約が定める値は、この
  文書が出所なので持たない。
- `injected`: ホストが自分で入れる引数であることの記録。**この項目も `inputs` に並べ、呼び出す側へは
  現れない**——常駐で保持しているものを渡させないが、どの引数をホストが埋めるかは表が持つ。
- `maxItems`: `element` を持つ項目に必須で、要素数の上限。**1以上の整数**とする。一次資料が
  その並びの要素数を定めているならその値とし、`source` を伴う。定めていなければ
  [要素数の上限](#要素数の上限)の規則で逆算した値とする。
- `minItems`: **空にできない項目だけ**が1を持つ。

#### 想定文字数

[一覧](#一覧)の `limit` の既定と最大は、要素1件をJSONへ写したときの**想定文字数**から逆算する。
想定文字数は[項目](#項目)ごとに次で決める。

- `members` を持つ項目は、**中の項目の想定文字数の和**に、名前と区切りのぶんとして**項目1件につき
  8文字**を足したものとする。
- `element` を持つ項目は、**要素の想定文字数に想定要素数を掛けたもの**とする。想定要素数は、
  `source` を伴う `maxItems` があればその値、無ければ**8**とする。
- `bounds` の上限を持つ項目は、**その上限をJSONの数値として書いたときの長さ**とする。値をそのまま
  読み書きできる最短の表記を採るので、桁が大きい値は指数の表記になる。
- ほかは[綴り](#表現の綴り)ごとに次のとおりとする。

| 綴り | 想定文字数 |
|---|---|
| `boolean` | 5 |
| `number` | 11 |
| `text` | 256 |
| `base64` | 256 |
| `enum_name` | 32 |
| `number_array` | 48 |
| `color` | 48 |
| `size` | 24 |
| `point` | 24 |
| `rectangle` | 48 |
| `font` | 299 |
| `brush` | 48 |
| `image` | 256 |
| `json` | 256 |
| `null_value` | 4 |

**表の値も、3つの数(項目1件あたり8文字・想定要素数8・一覧応答の枠1,000文字)も、すべて上限では
なく取り決めである。** 置いた根拠は次のとおりで、いずれも実測でも一次資料の定めでもない。

- 項目1件あたり**8文字**は、名前を引用符で囲んでコロンとコンマを添える `"name":,` の分として置く。
- 想定要素数**8**は、要素数の定めが無い並びの代表として置く。
- 一覧応答の枠**1,000文字**は、`value` の内側の `total` と `nextOffset` と配列の構文の分として置く。
- `boolean` は `false` の長さ、`null_value` は `null` の長さ。
- `number` は32bitの整数の最長の表記を代表として置く。この綴りは浮動小数も写し、その表記は
  これを超える。
- `text` と `base64` と `json` と `image` は長さの上限を持たないので、想定長として256。
- `enum_name` は列挙子の名前として32。
- 成分を並べる綴りは1成分あたり12文字として、`number_array` と `color` と `brush` と `rectangle` を
  4成分、`size` と `point` を2成分。**`number_array` の成分の数は型で決まり2から16まであるが**、
  4成分を代表として置く。
- `font` は書体名と大きさとスタイルの和(256 + 11 + 32)。

**想定を超える応答は一覧の件数縮小が吸収する**ので、これらの当否が効くのは既定件数の使い勝手だけで、
応答が枠に収まることの保証には関わらない。実運用で既定件数が過大・過小と分かった場合は、実際の応答
から1件あたりの文字数を測り直してこの表を置き換え、スキーマ正本を作り直す。

#### 要素数の上限

一次資料が要素数を定めていない並びの `maxItems` は、**[要求サイズ予算](#要求サイズ予算)から逆算した
値**と**[IPCの構造トークンの上限](pmx-editor-mcp-ipc.md#サイズ制限)から逆算した値**の**小さい方**と
する。どちらか一方だけでは受理されない要求を許してしまう——バイト数で収まっても構造トークンの上限は
ホスト基盤の判定として要求がツールへ渡る前に効く。

- **要求サイズ予算から**: 1件あたりの想定バイト数を**[想定文字数](#想定文字数)×4**(UTF-8の1文字が
  使う最大のバイト数)とし、要求サイズ予算をそれで割る(切り捨て・最小1)。
- **構造トークンから**: **構造トークンの上限から要求のエンベロープが使う分を差し引き**、残りを
  同時に指定できる可変長配列の数で等分して、その配列の予算とする。上限いっぱいを配列ごとに許すと
  合計で超えるからである。逆算は**その配列の予算 ÷(1件あたりの最大構造トークン数 + 1)**(切り捨て・最小1)と
  する。分母に1を足すのは要素の区切りの分で、M件の並びが使うトークンは「開き1 + 区切り M − 1 +
  要素の中身 M × t」= `M ×(t + 1)` だからである。

**1件あたりの最大構造トークン数**は、要素の形から次のとおり求める。組は「開き1 + メンバーの区切り
(メンバー数 − 1。メンバーが無ければ0)+ 各メンバーの値の再帰値」、並びは「開き1 + 最大件数 − 1 +
各要素の再帰値」、判別和は分岐の最大値、任意のメンバーは在る場合とする。空の組と空の並びも開きの1を
持つ。**並びが入れ子になるときは内側から決める**——外側の再帰値は内側の最大件数から決まるからである。

**要求のエンベロープが使う分**は、[IPCの要求の形](pmx-editor-mcp-ipc.md#メッセージ形式)の外枠と、
ツールが受け取る固定のメンバーが使うトークン数とする。**可変長配列のメンバー自身もここで数える**
——上の再帰値を0と置いたうえで、メンバーの区切りは可変長配列も含めたメンバーの総数で数える。配列の
手前の区切りは `M ×(t + 1)` に入らないので、ここで数えないと配列の数だけ上限を超えうる。

#### 一覧の件数

`limit` の逆算は、[応答サイズ予算](#応答サイズ予算の分け方)の**値の枠**から**一覧応答の枠1,000
文字**を引いたものを、要素1件の想定文字数で割る(切り捨て・最小1)。使うのは
[予算の未設定時の既定](pmx-editor-mcp-architecture.md#応答サイズ予算の設定)であって、その時々の
設定ではない——スキーマ正本は設定に依らず一つの値を持つ表だからである。**既定と違う予算で動く
ときも、この件数のまま受け取って一覧の件数縮小が吸収する**。

- **最大**は、[返す項目](#返す項目)で選べる項目のうち**最も小さいものだけを返す場合**の想定文字数で
  割った値とする。`hostOutput` の項目は選び方の外なので、どの呼び出しでも並ぶものとして和へ加える。
- **既定**は、**全項目を返す場合**の想定文字数で割った値の**半分**(切り捨て・最小1)とする。項目を
  絞らない呼び出しの使い勝手を、絞った呼び出しの都合で変えないためである。

## 検査

共通契約割当の照合が、次を検査する。

- 表の各項目の行キーが**提供対象のシグネチャに実在すること**。母集合の外の行キーを書けば落ちる。
- **戻り値がコネクタ型のシグネチャが、すべて表に在り、`connect` へ割り当てられていること**。
  常駐アクセスオブジェクトの取得は独立したツールを作らないので、1件でも表から漏れるとその
  シグネチャの割当先が決まらない。
- **解放・破棄のシグネチャが、すべて表に在ること**。同じ理由による。
- 表の**束縛が、シグネチャの引数・戻り値・レシーバーと過不足なく対応すること**。上の決め方で
  すべての束縛を導き、書かれた束縛と突き合わせる。書き落とした束縛も、余分に書いた束縛も、
  別のスロットへ書いた束縛もここで落ちる。
- 束縛したスロットが、**その割当で使えるスロットであること**。内部フローの取り違えは、そのフローに
  無いスロットを束縛していることで表に出る。
- **解放・破棄のシグネチャと、`targetHandle` を束縛する行が `tool` であり、その対象名が互いに
  揃っていること**。解放をホストが自分で呼ぶ流れへ書き替えると、台帳の失効と切り離された解放に
  なる。対象名は書き手が書く語なので、綴りの揺れをここで一つにそろえる。

**機械で確かめられるのはここまでである。** どの割当に当たるか——ツールが受け持つのか、共通引数に
なるのか、ホストが自分で呼ぶのか——と、その対象名が正しい綴りかは、そのシグネチャを何のために使うかの
判断で、列挙からは決まらない。解放のツールの対象名だけは行どうしで揃っていることを確かめられるが、
それ以外の対象名は突き合わせる先が無い。書き手が判じ、その判断を根拠の一文が後から
追える形にする、というところまでを規則とする。

能力対応表の照合が、次を検査する。

- 行の行キーが**提供対象のシグネチャに実在すること**。母集合の外の行キーを書けば落ちる。
- `capabilityIds` が、**その行キーを指す提供能力の集合と一致すること**。取り違えも書き落としも
  余分も、集合の食い違いとして表に出る。
- `direction` が、**シグネチャから決まる向きと一致すること**。
- `dangerKind` が、**危険操作の決め方の判定と一致すること**。当たらない行が種別を持つことも落ちる。
- 契約注記を持つ提供能力から出た行の `note` が、**台帳の注記の本文と一致すること**。転記なので、
  台帳を直せば対応表も直さなければ落ちる。
- `updateSpec` の `update` が、**`PEPlugin.Pmx.PmxUpdateObject` に実在する列挙子であること**。
- [用意の操作](#用意の操作)が足す要素型が**型役割表の要素名詞に実在すること**、サンプル値を引く
  型名が**公開API列挙に実在すること**、[参照元](#参照元)が指すSDKの引数が**その行のシグネチャに
  実在すること**。いずれも別の正本が持つ語なので、綴りの揺れをここで落とす。
- 共通契約割当行の集合が、[共通契約割当の正本](#共通契約割当の正本)の項目と**行キーで完全一致**し、
  `assignment`・`target`・`slotBinding` が一致すること。

**この照合が受け持つのは、表に載っている行である。** 母集合の全体が載っているかどうかは、
提供対象のシグネチャの集合と表の行キーの集合を突き合わせる別の照合が受け持つ。

**機械で確かめられるのはここまでである。** どの分類に当たるか、反映をどの範囲に限るかは、その
シグネチャが何へ作用するかの判断で、列挙からは決まらない——決まるのは、書かれた列挙子が実在するか
までである。書き手が判じ、その判断を根拠の一文が後から追える形にする。

スキーマ正本の照合が、次を検査する。

- 表が持つツールの集合が、[能力対応表](#能力対応表)が `tool` を持つ行のツールの集合と
  **完全一致すること**。片方にしか無いツールは、入出力の形か割り当て先のどちらかを失う。
- `shape` の綴りが、[表現の綴り](#表現の綴り)に**実在すること**。`array_of_` と `nullable_` で
  包んだ綴りは、要素を並べる形と `null` の許否をそれぞれ別の項目が持つので、ここには現れない。
- `payloads` の分岐の `type` が、能力対応表の[イベント行](#行の種別)が持つ `eventType` の集合と
  **完全一致すること**。
- `listing` の `limitDefault` と `limitMaximum` が、[一覧の件数](#一覧の件数)の規則で逆算した値と
  **一致すること**。書き写した値が古くなれば落ちる。
- [想定文字数](#想定文字数)の表の綴りが、[表現の綴り](#表現の綴り)の表と**過不足なく対応すること**。
  綴りを増やして想定文字数を足し忘れると、その綴りを使う一覧が現れるまで食い違いが表に出ない。
