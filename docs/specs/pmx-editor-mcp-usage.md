# pmx-editor-mcp 用途仕様書

**エンドユーザーがこの製品で何を成し遂げるか**の正本。何をツールへ写すか・どう写すか・どう検査するかは
別の仕様書が持ち、この文書はそれらの上位に立つ——**作業に現れないものは作らない**。

作業を成し遂げたいのはエンドユーザーで、ツールを呼ぶのはエンドユーザーが使うMCPクライアントの
エージェントである。**成功の条件に書く「何回の呼び出しで」は、MCPのツール呼び出しの回数を数える。**

## 作業

作業は次の6つとする。表の並びが優先順で、上ほど先に出す。成功の条件は、その作業が
**何回の呼び出しで、何が読み戻せる状態になるか**で書く。

| 優先順 | 作業 | 成功の条件 |
|---|---|---|
| 1 | モデルの構造の把握 | 要素の件数・名前・親子関係・材質と参照の一覧が、モデルの大きさによらず一定の呼び出し回数で読める。件数は1回、要素の一覧は種類ごとに1回で読め、応答が予算に収まらないときだけ続きの呼び出しが要る |
| 2 | 要素の一括編集と取り消し | 要素の追加と削除・名前の付け替え・材質や剛体のパラメータ・ボーンや頂点の位置を、対象が何件でも1回の呼び出しでまとめて変えられる。その1回がエディタの元に戻す1回で呼び出し前へ戻り、戻したあと作業1で読み直すと変更前の件数と値が読み戻せる |
| 3 | 保存と読み込み | パスを指定した保存・読み込み・別名保存が、それぞれ1回の呼び出しで済む。保存したファイルを読み込むと、作業1で読める件数と名前に加えて、保存前に変えた値と参照先が一致する |
| 4 | 見た目の確認 | 視点の設定1回とビューの画像の取得1回で、指定した視点の画像が得られる |
| 5 | モーションの構築 | ビルダの生成1回・キーフレームの登録1回・ファイルへの書き出し1回・ハンドルの解放1回で組み立てが済み、書き出したVMDを読み直すと登録したキーフレームが復元される |
| 6 | 画面の操作の受け取り | 購読1回と取得1回で、購読のあとにビューとUIモデルへ起きた操作が、起きた順に読み戻せる |

作業の境界は[共通契約仕様書](pmx-editor-mcp-common-contract.md)の
[編集の分類](pmx-editor-mcp-common-contract.md#編集の分類)・
[Undoの抑止](pmx-editor-mcp-common-contract.md#undoの抑止)・
[いつの状態を相手にするか](pmx-editor-mcp-common-contract.md#いつの状態を相手にするか)が定めるものを
そのまま使う。

## 非目標

次はツールにしない。**[能力台帳](pmx-editor-mcp-capability-ledger.md)のインベントリには残るが、
MCPのツールとしては公開しない。** 台帳の分類はSDKのシグネチャを技術的にツール化できるかで付く
もので、台帳自身が公開の可否を定めないと断っている。[共通契約仕様書](pmx-editor-mcp-common-contract.md)の
[危険操作](pmx-editor-mcp-common-contract.md#危険操作)がどのシグネチャを危険と決めるかも同じく
シグネチャの分類であって、公開の可否ではない。**公開するかどうかを決めるのはこの文書である。**

| 非目標 | 理由 |
|---|---|
| エディタ終了 | どの作業にも現れず、誤って呼ばれたときに失うものが最も大きい |
| VMEの演算子テンプレート | 作業5が要るのはキーフレームの組み立てまでで、演算子の合成は要らない |
| PMDレガシー | 対象はPMXで、PMDは読み書きの経路を二重に持つだけになる |
| 未追加オブジェクトグラフのトランザクション | 作業2の取り消しはエディタの元に戻すで足り、未追加の生成物に別の巻き戻しを設けると戻り先が二重になる |

**画面の操作(ビューとUIモデルのイベント)は非目標ではない。** 作業6として持ち、5つの作業の
あとに置く。

## 製品の要件

作業のどれにも先立って満たすものを3つ置く。

### 危険操作の境界は、ツールの分離とクライアント側の許可で作る

`confirm` は**境界ではない**。エージェント自身が真を渡すので、渡すことを学べば素通りする。
エンドユーザーが止められるのは、**MCPクライアントがツールごとに求める許可**と、**エディタの
プラグインメニューからのホスト停止**の2つだけである。したがって:

- **上書き保存とモデル初期化は、読み取り・編集のツールと別のツールにし、名前で区別できるように
  する。** エンドユーザーがツールの名前だけを見て許可を決められることを条件とする。
- `confirm` は残す。ただしその意味は「**取り返しの付かない操作と知って呼ばれた**」という記録で
  あって、境界ではない。
- エディタ終了はツールにしない(非目標)。

### SDKの版が違っても待受を止めず、断るのは解決できないツールだけにする

ホストが参照するSDKは、実行時にエディタ同梱の版が読み込まれる。新しい版でメンバーが増えても
既存のツールは動くので、**版番号の不一致で全部を止めても、エンドユーザーには何も渡らない**。

- **解決できないメンバーを使うツールだけを個別に断り、ほかのツールは動き続ける。**
- **稼働しているSDKの版が分かるようにする。**

いつ中継先を解決するか、版をどの項目で知らせるかは、下位の仕様書が定める。

### 標準のMCPで動く製品にし、特定のクライアントに縛られない

stdioの標準のMCPで動くことを要件とし、**Claude Code は検証に使う参照クライアントに留める**。

- **Claude Code でしか成り立たない機能を作らない。**
- 特定のクライアント向けの拡張は、**それを解さないクライアントが無視するだけで壊れない範囲**で
  あれば使ってよい。ただし応答の大きさを抑える手立ては、その拡張が無いクライアントでも働くように
  する。
- 応答サイズ予算の既定は、**設定で変えられる形のまま置く**。

## 受入シナリオとの対応

[検証手順書](../conventions/verification.md#受入シナリオ)の受入シナリオが、どの作業を確かめるかを
次のとおり対応づける。**9本のどれも、いずれかの作業に対応する。** ただし各シナリオが確かめるのは、
対応する作業の成功の条件のうち**そのシナリオが実際に通る範囲**であって、条件の全部ではない。
**残りをどう確かめるかは、この文書では定めない。**

| 受入シナリオ | 作業 | そのシナリオが確かめること |
|---|---|---|
| 1 導入と初期化 | 1 | 導入した状態から疎通し、モデル初期化で作業1の開始状態を作れること |
| 2 読み取り | 1 | モデル情報と要素の一覧が読めること |
| 3 編集と取り消し | 2 | 追加と更新の1回が、エディタの元に戻す1回で戻ること。削除は通らない |
| 4 保存の確認要求 | 3 | 保存が確認の有無で分かれ、指定したパスへ書けること。読み込みと読み戻しは通らない |
| 5 ビュー | 4 | ビューの画像が、縮小の指定の有無それぞれで得られること。視点の設定は通らない |
| 6 イベント | 6 | 購読したビューとUIモデルの操作が、起きた順に取れること |
| 7 モーション | 5 | ビルダで組み立て、ハンドルを解放できること。ファイルへの書き出しと読み直しは通らない |
| 8 エラー系 | 1 | (a)は作業1の呼び出しが、範囲外の指定でそれと分かる形で断られること。(b)(c)はどの作業にも共通の前提で、エディタ未起動と切断の伝わり方を `ping` で確かめる |
| 9 複数エディタ | 1 | 待受が複数あるあいだは `ping` に曖昧さがそれと分かる形で返り、待受が1つになると作業1の呼び出しがその相手へ届くこと。これもどの作業にも共通の前提である |
