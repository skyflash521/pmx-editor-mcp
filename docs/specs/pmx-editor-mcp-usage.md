# pmx-editor-mcp 用途仕様書

**エンドユーザーがこの製品で何を成し遂げるか**の正本。何をツールへ写すか・どう写すか・どう検査するかは
コードとテストと機械可読の正本が持ち、この文書は**何を目標にするか**だけを持つ。

作業を成し遂げたいのはエンドユーザーで、ツールを呼ぶのはエンドユーザーが使うMCPクライアントの
エージェントである。**成功の条件に書く「何回の呼び出しで」は、MCPのツール呼び出しの回数を数える。**

## 作業

作業は次の6つとする。成功の条件は、その作業が**何回の呼び出しで、何が読み戻せる状態になるか**で書く。

| 作業 | 成功の条件 |
|---|---|
| モデルの構造の把握 | 要素の件数・名前・親子関係・材質と参照の一覧が、モデルの大きさによらず一定の呼び出し回数で読める。件数は1回、要素の一覧は種類ごとに1回で読め、応答が予算に収まらないときだけ続きの呼び出しが要る |
| 要素の一括編集と取り消し | 要素の追加と削除・名前の付け替え・材質や剛体のパラメータ・ボーンや頂点の位置を、対象が何件でも1回の呼び出しでまとめて変えられる。その1回がエディタの元に戻す1回で呼び出し前へ戻り、戻したあとモデルの構造の把握で読み直すと変更前の件数と値が読み戻せる |
| 保存と読み込み | パスを指定した保存・読み込み・別名保存が、それぞれ1回の呼び出しで済む。保存したファイルを読み込むと、モデルの構造の把握で読める件数と名前に加えて、保存前に変えた値と参照先が一致する |
| 見た目の確認 | 視点の設定1回とビューの画像の取得1回で、指定した視点の画像が得られる |
| モーションの構築 | ビルダの生成1回・キーフレームの登録1回・ファイルへの書き出し1回・ハンドルの解放1回で組み立てが済み、書き出したVMDを読み直すと登録したキーフレームが復元される |
| 画面の操作の受け取り | 購読1回と取得1回で、購読のあとにビューとUIモデルへ起きた操作が、起きた順に読み戻せる |

作業の境界は[共通契約仕様書](pmx-editor-mcp-common-contract.md)の
[編集の分類](pmx-editor-mcp-common-contract.md#編集の分類)・
[Undoの抑止](pmx-editor-mcp-common-contract.md#undoの抑止)・
[いつの状態を相手にするか](pmx-editor-mcp-common-contract.md#いつの状態を相手にするか)が定めるものを
そのまま使う。

## 製品の要件

作業のどれにも先立って満たすものを4つ置く。

### 台帳が提供と分類した能力は、すべてツールとして公開する

何を公開するかは[能力台帳](../../data/observed/capability-ledger.json)が決める。台帳が提供と分類した
能力は、危険な操作も含めて1つ残らずMCPのツールにする。**公開面を絞らない**——どれが要るかは
製品を使ってみるまで分からず、使う前に絞れば、要る機能を落としたかどうかを確かめる手立てが無い。
誤って呼ばれると失うものが大きい操作の境界は、次の要件が作る。

### 危険操作の境界は、ツールの分離とクライアント側の許可で作る

`confirm` は**境界ではない**。エージェント自身が真を渡すので、渡すことを学べば素通りする。
エンドユーザーが止められるのは、**MCPクライアントがツールごとに求める許可**と、**エディタの
プラグインメニューからのホスト停止**の2つだけである。したがって:

- **上書き保存・モデル初期化・エディタ終了は、読み取り・編集のツールと別のツールにし、名前で
  区別できるようにする。** エンドユーザーがツールの名前だけを見て許可を決められることを条件とする。
- `confirm` は残す。ただしその意味は「**取り返しの付かない操作と知って呼ばれた**」という記録で
  あって、境界ではない。

### SDKの版が違っても待受を止めず、断るのは解決できないツールだけにする

ホストが参照するSDKは、実行時にエディタ同梱の版が読み込まれる。新しい版でメンバーが増えても
既存のツールは動くので、**版番号の不一致で全部を止めても、エンドユーザーには何も渡らない**。

- **解決できないメンバーを使うツールだけを個別に断り、ほかのツールは動き続ける。**
- **稼働しているSDKの版が分かるようにする。**

### 標準のMCPで動く製品にし、特定のクライアントに縛られない

stdioの標準のMCPで動くことを要件とし、**Claude Code は検証に使う参照クライアントに留める**。

- **Claude Code でしか成り立たない機能を作らない。**
- 特定のクライアント向けの拡張は、**それを解さないクライアントが無視するだけで壊れない範囲**で
  あれば使ってよい。ただし応答の大きさを抑える手立ては、その拡張が無いクライアントでも働くように
  する。
- 応答サイズ予算の既定は、**設定で変えられる形のまま置く**。
