# pmx-editor-mcp 配布と導入

配布物の組み立てと、開発の環境へ入れる手順の正本。

## ビルドとデプロイ

### PMXエディタ導入ディレクトリの指定

PMXエディタの導入先は環境ごとに異なるため、リポジトリ直下のGit管理外ファイル `local.props`
(`.gitignore` に登録済み)へ `PmxEditorDir` プロパティとして定義する。追跡下の
[Directory.Build.props](../../Directory.Build.props) が行うのはImportだけで、`local.props` が
存在するときだけ読み込む(無い環境ではImportをスキップするだけで、`Directory.Build.props` の
評価は失敗しない)。

未定義のまま進むことを止めるのはホストcsprojの `EnsurePmxEditorDir` ターゲットで、ビルドと
デプロイの前に走り、`PmxEditorDir` が空なら「local.props に PmxEditorDir を定義せよ」という
明示エラーで失敗させる。

### バージョンの正本

バージョンは、リポジトリ直下の [Directory.Build.props](../../Directory.Build.props) の `Version`
プロパティを**単一の正本**とする。ホストとブリッジのアセンブリのバージョンも、配布する
パッケージの名前も、この値を共有する。**初版は `0.1.0`** とし、以後は配布のたびに手で上げる
——自動で採番しない。

### 配布パッケージ

配布するのは `dist/pmx-editor-mcp-<バージョン>.zip` で、`dist/` はGitの管理外に置く。**内容は次の
5点だけ**とする。

- `PmxEditorMcp.dll`(ホスト。Releaseビルド)
- `PmxEditorMcp.Bridge.exe`(ブリッジ)
- `README.txt`(エンドユーザー向けの手順の正本。追跡下のテンプレート `docs/guides/package-readme.txt` を
  無加工で収める。持つ手順は下記のとおりで、**単体で導入を完了できる全手順**とする。配布先では
  リポジトリ内のパスを解決できないので、参照だけの記載にしない)
- `LICENSE.txt`(リポジトリの `LICENSE` 全文の複製)
- `THIRDPARTY.txt`(第三者ライセンス表示。正本は追跡下の `docs/guides/package-thirdparty.txt`)

**生成は `pwsh scripts/package.ps1` の1コマンドで完結する。** スクリプトは(1)ホストのRelease
ビルド、(2)ブリッジの自己完結・単一ファイル発行、(3)zipの作成、(4)**内容物検査**を行い、検査に
落ちたら失敗させる。内容物検査は次を見る——上の5点が在ってそれ以外が無いこと/`PEPlugin.dll` が
混じっていないこと/`README.txt`・`LICENSE.txt`・`THIRDPARTY.txt` がそれぞれの正本とバイトで一致
すること/下記の**依存集合の照合**。

#### 同梱する `README.txt` が持つ手順

テンプレートは、次を**単体で導入を完了できる形**で持つ。

- **前提**: Windows 10(バージョン1903以降)または Windows 11 の x64、PMXエディタ(x64版)、
  Claude Code CLI。**.NETランタイムの追加の導入は要らない**——ブリッジは自己完結で発行し、ホストが
  使う .NET Framework 4.8 は上記のOSに同梱されている。
- **導入**: (1)**専用の新しいフォルダを作り**、その中へzipを展開する(既存のフォルダへ直接
  展開しない——アンインストールでフォルダごと削除するためである)。(2)`PmxEditorMcp.dll` を
  PMXエディタの導入フォルダの `_plugin\User` へコピーする。(3)
  `claude mcp add --scope user pmx-editor-mcp -- "<展開先の PmxEditorMcp.Bridge.exe の絶対パス>"`
  で登録する。パスは空白を含みうるので**引用符で囲む**——コマンドの例も引用符つきで載せる。
  **エンドユーザー向けの登録と削除は、すべて `--scope user`(ユーザースコープ)で統一する**——実行
  ディレクトリに依らず、どのプロジェクトからでも同じ登録を使えるためである。開発者向けのローカル
  スコープの登録とは別物であることも書く。(4)PMXエディタを起動し、Claude Code から `ping` の応答
  ("pong")で導入を確かめる。
- **エディタが複数のとき**: **登録は一度だけで、エディタを起動し直しても登録し直さない**。接続先は
  ブリッジが待ち受けているホストの列挙で決まるので、エディタが複数起動していても、ホストが待ち
  受けているエディタが1つなら自動で決まる。2つ以上のホストが待ち受けているときは接続先を決め
  られないという誤りになり、候補のパイプ名が並ぶ。その場合は、対象にしないエディタのプラグイン
  メニューからホストを停止して待受を1つに絞る。ツールの応答が先頭の行で接続先のパイプ名を名乗る
  ことと、接続先が別のエディタへ移ったときはその旨が本文に出ることも書く。
- **更新**(順序を確定する): (1)Claude Code のセッションを終了する(ブリッジのプロセスを止める)。
  (2)PMXエディタを終了する。(3)展開先と `_plugin\User` の同名のファイルを新しいzipの内容で上書き
  する。(4)PMXエディタを起動する(ホストのDLLは次にエディタを起動したときから有効になる)。
  (5)Claude Code を開始し、`ping` の応答を確かめる(エディタのプロセスIDが変わっても登録の操作は
  要らない)。
- **アンインストール**(順序を確定する): (1)Claude Code のセッションを終了する(ブリッジのプロセスを
  止める。実行中はexeがロックされていて削除に失敗する)。(2)
  `claude mcp remove --scope user pmx-editor-mcp`。(3)PMXエディタを終了する。(4)`_plugin\User` の
  `PmxEditorMcp.dll` と、導入のときに作った専用の展開フォルダを削除する。
- **トラブルシューティング**: ダウンロードしたzipに由来するブロック属性でホストのDLLが読み込まれ
  ないときの解除の手順(エクスプローラーのプロパティから許可する)を載せる——パッケージ単体で
  復旧できるようにするためである。

#### 第三者ライセンス表示の形

`docs/guides/package-thirdparty.txt` は次の形とする。

**先頭に機械照合のブロック**を置く。`-----BEGIN PACKAGE LIST-----` と `-----END PACKAGE LIST-----`
で挟み、1行1項目で `<パッケージID(小文字へそろえたもの)> <バージョン>` を(ID,バージョン)の昇順・
重複なしで並べ、末尾に `sdk <ビルドに使うSDKのバージョン>` の1行を置く。**解析の対象**はホストと
ブリッジの2つのプロジェクトの `dotnet list package --include-transitive --format json` の和とし、
**除外リスト**(追跡下の `docs/guides/package-excluded-packages.txt`。1行1パッケージID)を当てて
除く。**除外リストへ足してよいのは、コンパイルの参照だけで発行の出力に含まれないビルド専用の
パッケージ**であり、足すときは当該のアセンブリが発行の出力に無いことを確かめる。依存を変えたときの
第三者ライセンス表示の更新は、下記の依存集合の照合が落ちることで強制される。同じIDが違うバージョンへ解決されたときは、(ID,バージョン)の組で一意なので双方を並べる。

**NuGet依存のエントリ群**は、対象のパッケージごとに次の形で置く。1行目は見出し
`## <パッケージID> <バージョン>`、2行目は `license: <SPDXライセンス式>`、続けて `source:` の行
(複数可)、続けて `-----BEGIN LICENSE <パッケージID>-----` と `-----END LICENSE <パッケージID>-----`
の間に転記の本文を置く。`source:` の行は2種類とする——`source: files <パッケージ内の相対パスをセミ
コロンで区切ったもの>`(NuGetのキャッシュ内でそのパッケージに同梱されるライセンス・NOTICE類の全部。
複数あるときはファイル名の昇順に連ねる)と、`source: spdx <ID>`(SPDXライセンス式が指す標準の本文。
正本は追跡下の `docs/guides/licenses/<ID>.txt` で、SPDXライセンスリストから転記して作り、以後は
この追跡ファイルと照合する——外部の版に依らないためである)。**パッケージ本体のライセンス本文が
同梱のファイルに含まれないとき(NOTICEだけを同梱している等)は、両方の `source:` の行を併記する。**

**転記の本文は次の順で連ねる**——spdxの標準本文(併記のときは先頭。IDが複数あるときはID順)、続けて
同梱の各ファイル(ファイル名の昇順)。**各要素の直前には必ず区切りの行を置く**(先頭の要素にも
置く)。区切りの行は、spdxの本文が `--- spdx <ID> ---`、ファイルが `--- <ファイル名> ---` とする。
ライセンス本文が同梱されていればfilesだけ、同梱のファイルが皆無ならspdxだけとする。

**「.NETランタイム」の見出し**を置き、自己完結の発行で同梱されるランタイム自体のライセンスと第三者
通知として、ビルドに使う .NET SDK の導入ディレクトリに同梱される LICENSE.txt と
ThirdPartyNotices.txt の**全文**を、それぞれ `-----BEGIN RUNTIME LICENSE-----` と
`-----BEGIN RUNTIME NOTICES-----`(対応するEND)で挟んで転記する。

**ハッシュの正規化**は、UTF-8でデコードしてBOMを外し、改行をLFへそろえ、末尾の改行を落としたバイト
列のSHA-256とする。範囲を挟むマーカーの行そのものは範囲に入れない(BEGINの行の直後からENDの行の
直前まで)。

**依存集合の照合**は次のすべてを見る。

- 照合ブロックのパッケージ一覧が、解析の結果(同じそろえ方・同じ並び・除外を当てたもの)と過不足
  なく一致すること。消えた依存が残っていることも、ここで落ちる。
- `sdk` の行が、ビルドに使うSDKのバージョンと一致すること。
- 本文のランタイムの転記範囲(RUNTIME LICENSE と RUNTIME NOTICES の各マーカーの間)の正規化した
  ハッシュが、ビルドに使うSDKに同梱される原本のハッシュと一致すること。
- 照合ブロックの各(ID,バージョン)が本文の見出しと過不足なく対応し、各エントリが空でない
  `license:` の行と `source:` の行を持ち、転記範囲の正規化したハッシュが「`source:` が指す転記元
  から上の連ね方で作った本文」のハッシュと一致すること。
- 各エントリの `source: files` の集合が、NuGetのキャッシュ内でそのパッケージが持つライセンス・
  NOTICE類のファイルの機械列挙(名前が LICENSE*・NOTICE*・THIRD-PARTY*・COPYING* に当たるもの。
  大文字と小文字は区別せず、全階層を見る)と一致すること(漏れゼロ)。`license:` の行がパッケージの
  メタデータと合い、ライセンス本文を同梱しないパッケージが `source: spdx` の行を必ず持つこと
  (NOTICEだけを同梱するときにSPDXの併記を落としていないかを見る)。

### PEPlugin.dll の参照

`$(PmxEditorDir)\Lib\PEPlugin\PEPlugin.dll` を HintPath で参照する。ホストは `Private=false` とし、
配布物のDLLを成果物へコピーしない。PMXエディタ配布物の利用規約がパッケージ内データの再配布を
禁じているため、各自の導入物を参照するだけにする。

**テストは `Private=true` とし、ビルド出力へ複製する。** テストはエディタと別のプロセスで動き、
そのプロセスには配布物が読み込まれていないので、複製しなければSDKの型を実装した差し替えを読み込め
ない。ビルド出力は配布物にも版管理にも入らないため、再配布には当たらない。

### デプロイ

ホストcsprojの `Deploy` ターゲット(`Build` に依存)が、成果物を
`$(PmxEditorDir)\_plugin\User\` へ変更時のみコピーする。

```
dotnet build src/HostPlugin/PmxEditorMcp.HostPlugin.csproj -t:Deploy
```

**ホストDLLの置き場はこの1つとする。** 2箇所に置くとエディタは両方を読み込み、同じ名前の待受が
2つになって後発が待受を作れない。デプロイはすべてのエディタを終了してから行い、反映は次回の
エディタ起動からになる——起動中のエディタは読み込み中のDLLを掴んでおり、同じ名前での上書きは
配置先のロックで失敗する。
