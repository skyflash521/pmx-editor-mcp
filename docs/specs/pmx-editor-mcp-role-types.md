# pmx-editor-mcp 役割対象仕様書

**役割対象の型**——型ごとの役割を割り当て、日本語名を付ける対象になる型——の母集合の決め方を定める。
日本語名の正本と型役割表はどちらもこの母集合を鍵にするので、決め方をそれぞれへ書くと食い違う。

母集合はSDKの公開API列挙と[能力台帳](pmx-editor-mcp-capability-ledger.md)から機械で導く。
除外一覧もこの2つから導く値で、追跡下には置かない。**本書は母集合の値を持たない。**

## 除外

提供対象から除くシグネチャは、能力台帳と公開API列挙から次の順で決める。上から順に見て、最初に
当たった1つとする。

1. **凍結した組**: 生成器が能力ごとに名指しした行キーの集合。名指しは行キーそのものか、型か
   名前空間の単位か、**まとめて指した名前空間の型を `PEPlugin.IPEBuilder` が作る生成メンバー**の
   単位である(生成メンバーはその名前空間の外で宣言されるので、名前空間では選べず、作る型の側から
   選ぶ)。能力の行が指すシグネチャ全体とは限らない。生成器は名指しに加えて、凍結した
   ときの台帳の分類と対象——備考を根拠に含めた能力ではその備考も——の写しを持ち、台帳がそれと
   食い違えば止まる。**いま台帳に書かれている備考は根拠にしない**——後から書き足せるので、除外の
   集合が後付けで広がる。
2. **Cプラグイン引数**: 引数にCプラグインそのものの型を取る。コネクタの型は当たらない。
3. **デリゲート系**: デリゲート型を値として受け渡す。イベントの宣言は、ハンドラがデリゲート型でも
   購読の仕組みで扱うので当たらない——イベントで見るのは引数の型だけとする。
4. **PMD系**: 引数か戻り値にPMDのデータ型を含み、**PMXの代替が在る**もの。メンバー名だけがPMDを
   含むもの——保存のメソッドなど——は当たらない。
5. **PMDモデル系**: 引数か戻り値にPMDのモデル本体を含む。上でPMXの代替が見つからなかったものが
   ここへ落ちる。
6. **コンストラクタ重複**: コンストラクタのうち、**同じ型を作る、それ自身が除外されないメソッドが
   在る**もの。その型自身が宣言するメソッドは当たらない。

**PMXの代替**とは、同じ宣言型・同じメンバー名・同じ総称型引数の数・同じ戻り値・同じ引数の個数を
持ち、引数の型がPMD型とPMX型の対応で置き換わっていて、**それ自身が除外されない**シグネチャを
いう。対応する組は `PEPlugin.Pmd.IPEPmd` に対する `PEPlugin.Pmx.IPXPmx` の1つだけとする。

**Stream系は種別で決めない。** 形式が一次資料でしか決まらず、機械では除外の可否を判断できない。
凍結した組に無い、引数か戻り値にStream——`System.IO.Stream` 自身と、それを継承する型——を持つ
シグネチャを見つけたら、
その行キーを示して止める。止まったら形式を一次資料で確かめ、**ファイルパス版の代替があれば**台帳の
非対応件数を直して凍結を取り直し、**代替が無ければ**そのシグネチャを除外しないものとして提供対象に
残す。

## 提供対象から辿る

能力台帳の提供行が担当する公開シグネチャのうち、除外一覧に無いものを**提供対象**とする。提供対象の
シグネチャに現れる型——宣言型・引数の型・値の型——を集め、そこから母集合に入った型の基底型を推移的に
辿る。型を辿るときは配列と参照渡しの印を外し、総称型はその段の型引数まで開く。辿り着いた型は次の
いずれかになる。

- **値の表現で写せる型**: 数値・文字列・真偽・列挙・ベクトルのように、応答へ値として埋め込める型。
  母集合に入らない。
- **総称型引数**: 宣言ごとに別の型になり、それ自身は役割を持たない。どちらにも入らない。
- **デリゲート型**: 呼び出し側が実装を渡すもので、値としても操作の対象としても写せない。
  イベントのハンドラ型もこれに当たる。どちらにも入らない。
- **それ以外**: 母集合に入る。

対象アセンブリの外で宣言された型は、**提供対象のシグネチャに直接現れるときだけ**母集合に入る——
イベント引数の型がこれに当たり、その型の項目も応答へ埋め込むためである。基底型として辿り着いただけの
外部の型は入らない。

## 接続の根から辿る

接続初期化が辿り始める型を**接続の根**と呼ぶ。プラグインが起動時に受け取る引数と、Cプラグインの
静的な橋渡しがこれに当たる。**根の一覧は公開API列挙ツールが値として持ち、その並びが根の並びで
ある**——道が複数あるときにどれを採るかがこの並びで決まる。台帳はこれらへ能力の行を
作らないので、根とその先の型は提供対象のシグネチャに現れず、上の経路だけでは母集合から漏れる。
接続初期化は必ずここを通るので、役割を持たなければ表が接続の経路を語れない。

根から先へ進む一歩は次の2つとする。

- 引数の無い取得プロパティ。
- 自動注入コネクタだけを引数に取り、値を返すメソッド。ホストが常駐保持するものへ辿り着くとき、この
  コネクタは呼び出し側が用意せずに渡るので、引数があっても経路は途切れない。

型が宣言するメンバーだけでなく、基底型から継いだメンバーも一歩に数える。自分ではメンバーを宣言せず
基底型のものだけを持つ型が実在し、これを外すとその型から先が辿れない。

**根から辿り着け、かつそこから前節で母集合に入った型のいずれかへ辿り着ける型**を母集合へ加える。
加えないのは、そこから前節の型へ至らない枝と、値の表現で写せる型である。

**列挙に無い根があれば、母集合を決めずに止める。** 根の名前が実物と食い違ったまま黙って母集合が縮むと、
落ちた型が役割を持たないまま検査を通る。
