# pmx-editor-mcp ツール仕様書

SDKの公開メンバーを、MCPクライアントへ見せるツールへどう写すかを定める。値の表現・応答の包み・
共通の引数・入出力の形と受け手は[共通契約仕様書](pmx-editor-mcp-common-contract.md)、型の役割と
型ごとのツールの名前は[型役割仕様書](pmx-editor-mcp-type-roles.md)が持つ。

## メンバーから決まるツール名

型の役割ごとのツールの名前は
[型役割表](pmx-editor-mcp-type-roles.md#正本の形)が定める規則から導く。ここが定めるのは、それ以外の、
メンバーから名前が決まるツールである。**能力対応表の行は名前を書かず**、行が採る種別がツールを持つと
決めた行について、要るときにこの規則から導く。

[動作の語](pmx-editor-mcp-common-contract.md#ツールの説明文)は、シグネチャのメンバー名を
PascalCaseからsnake_caseへ**機械変換**したものとする。ただし**公開コンストラクタから作るツール**は、
その動作の語を `create_<型役割表の要素名詞(単数形)>` として機械変換の例外とする——コンストラクタ
には変換元のメンバー名が無いためである。生成を受け持つメソッドはメンバー名を持つので、例外に
当たらない。

**担当群は宣言型から取る。** 作る型から取ると、同じ名前のツールの行が宣言型ごとに分かれ、
[説明文](pmx-editor-mcp-common-contract.md#ツールの説明文)が求める「同じ名前の行の宣言型がすべて
同じであること」と食い違う。ファイルの入出力のメソッドも例外にしない。

**出所修飾**——型役割表の要素名詞(単数形)——は、型の公開メソッドでは衝突の有無によらず付け、
コネクタ型のメソッドでは同じ担当群の中で**2つ以上のツールに現れる動作の語**を持つときだけ付ける。
同名のオーバーロードは1つのツールへ集まるので、衝突は行の数ではなくツールの数で数える。型の公開
メソッドで常に付けるのは、同じはたらきのメソッドが型をまたいで現れるためである。**動作の語を例外
とした生成のツールは出所修飾を持たない**——何を作るかは、その動作の語の要素名詞が既に表している。

## メンバーの写し方

- **メソッドは1メソッド=1ツール**とする。メソッドは引数の構成と意味が個別なので、集約すると
  入力のスキーマが分岐の集合になり、検索でツールを引けなくなる。
- **受け手が操作対象型の要素であるメソッドは、受け手を
  [対象の集合](pmx-editor-mcp-common-contract.md#対象の集合)で受け取り、1回の呼び出しで対象集合の
  全要素に対して呼ぶ。** 入力に現れる引数は、対象集合の**全要素へ同じ引数**を配る `args`(引数の
  組1つ)か、対象集合と**同じ長さ**の `argsList`(引数の組の配列)のどちらかへ入れる。2つは相互
  排他で、両方を持つことも、どちらも持たないことも、長さが食い違うことも
  引数が不正とする。入力に現れる引数を
  1つも持たないメソッドは、そのどちらも受け取らない。応答は、**戻り値か出力に現れる引数を持つ
  メソッド**では対象集合と同じ長さの配列とし、どちらも持たないメソッドでは**呼び出した要素の
  件数 `invoked`** とする——1回の呼び出しが対象集合の全要素に及ぶので、何件へ及んだかが唯一の
  結果情報になる。
- **プロパティは1件ずつ写さず、宣言型ごとに集める**。コネクタ型のプロパティは型役割表が持つ取得と
  更新の2つへ、ハンドル操作型と操作対象型のプロパティは同じく型役割表が持つ一覧と更新の2つへ集める。
  プロパティは引数を持たず値の読み書きしかしないので、メソッドと違い集めても入力のスキーマは
  分岐しない。
- **抽象の型を並べるリストでは、具象の型のプロパティとフィールドを
  [`itemType` の分岐](pmx-editor-mcp-common-contract.md#抽象の型を並べるリスト)へ写す。** 具象の型
  の公開メソッドはこの分岐へ入れず、上のメソッドの規則どおり独立したツールへ写す。
- **公開フィールドはプロパティと同じ規則で扱う。** 読み書きの向きは機械で判定する。コレクションを
  返す取得のプロパティは、そのコレクションのツールが扱うので更新の対象にしない。
- **公開イベントは、[イベントを取り出す合成ツール](pmx-editor-mcp-common-contract.md#合成ツール)の
  分岐へ写す。** イベントのメンバーごとに分岐を持ち、その
  [種別の識別子](pmx-editor-mcp-common-contract.md#イベント)は、宣言型の
  [要素名詞(単数形)](pmx-editor-mcp-type-roles.md#正本の形)と**イベント名を機械変換したもの**を
  ピリオドでつないだ形とする。型をまたいで同じ名前のイベントがあるので、イベント名だけでは
  分かれない。リスナを作るツールが作ったリスナは、**扱うイベントの全種が取り出しに現れ、解放した
  後は現れない**。
- **公開コンストラクタは、ハンドル操作型では生成のツールへ写す。** コンストラクタが複数ある型は
  同じツールの呼び分けとし、入力で機械判別する。判別できない組は**分岐を選ぶ項目**を置き、引数の
  型の[表現の綴り](pmx-editor-mcp-common-contract.md#表現の綴り)をその値として分ける——名前を
  変えても入力は変わらないので、名前では分けられない。イベント引数型とDTO型のコンストラクタは
  独立したツールを作らず、埋め込み先のスキーマの入力からホストが内側で組み立てる。
- **同じツールへ集める同名のオーバーロードは、JSONへ写した入力で相互に機械判別できなければ
  ならない**。判別に使うのは呼び出す側が必ず渡す項目の名前と形で、出力だけに現れる引数は含めない。
  判別できない組(文字列の版とバイト列の版がどちらもJSONの文字列になる場合など)は同じツールへ
  集めず、違いのある引数の[表現の綴り](pmx-editor-mcp-common-contract.md#表現の綴り)を後ろに付けた
  別のツールへ分ける。

## 型の役割ごとの写し先

役割の定義と評価の順は[型役割仕様書](pmx-editor-mcp-type-roles.md#役割)が持つ。

- **コネクタ型・操作対象型・ハンドル操作型**: メンバーを上の
  [メンバーの写し方](#メンバーの写し方)どおりに写す。ハンドル操作型の受け手を集合で受け取るのは、
  単数にするとVMDのキーやUIモデルの操作が対象の数に比例した呼び出しになり、操作対象型だけを集合に
  した意味が失われるためである。
- **イベント引数型**: 独立したツールを作らず、読み取れる全プロパティをそのイベントの `payload` の
  スキーマへ埋め込む。
- **DTO型**: 独立したツールを作らず、プロパティを方向ごとに(応答へは読み取れる全項目、入力へは
  書き込める全項目)関わるツールの入出力のスキーマへ埋め込む。

## ハンドルを発行するツール

**[ハンドルを新しく発行する](pmx-editor-mcp-type-roles.md#ハンドル発行の判定)ツールは、1回の
呼び出しで複数を発行できる。** 所有するリストへ加えられるのは発行したハンドルだけなので、発行が
1件ずつだと、N件を加えるのに発行N回と追加1回が要り、対象を集合にした意味が失われる。

**引数を持つかどうかは、呼び出し側が渡す引数——ホストが自分で入れる引数と、共通契約が束縛する引数を
除いたもの——で決まる。** SDKのシグネチャが引数を取っていても、その全部をホストが入れるなら、その
ツールは引数を持たない。

- **公開のコンストラクタとコネクタのメソッド**は、渡す引数が無いなら**発行する数 `count`(最小1)
  だけ**を受け取る。渡す引数があるなら、**全件へ同じ引数を配る `args` と `count` の組**か、**要素
  ごとの引数の組の配列 `argsList`**(その長さが発行する数になる)のどちらかとし、2つは相互排他で、
  両方を持つことも、どちらも持たないことも
  引数が不正とする。
- **受け手に紐づくメソッド**は、**受け手1件につき1個**を発行し、`count` を持たない。受け手の集合と
  発行する数を別々に取ると、積を作るのか総数なのか、`argsList` の長さがどちらに対応するのかが
  決まらない。引数は `args` と `argsList` の二択とし、渡す引数の無いメソッドはどちらも受け取らない。

**応答は発行した順のハンドルの並び**とする。受け手に紐づくものでは、受け手を解いた順と同じ並び・
同じ長さになる。

## モーションイベントのテンプレート

[能力台帳](../../data/observed/capability-ledger.json)があらかじめ定めたテンプレートで提供すると定める
モーションイベントの操作は、**そのテンプレートを指す形**で受け取る。評価の順とフレームの意味は
SDKの実行系に従う——ホストは自分の評価器を持たない。

テンプレートは `type`・`targets`・`frames`・`params` の4つで指す。どれも書き手が選べず、シグネチャ
から導く。

- **`type`**: 宣言型の[要素名詞(単数形)](pmx-editor-mcp-type-roles.md#正本の形)と、**メンバー名を
  機械変換したもの**をピリオドでつないだ形とする。同じ名前のメンバーを持つ別の演算子の型とは
  重ならない。
- **`targets`**: 適用する対象の集合。位置でもハンドルでも指せないので、
  [対象の集合](pmx-editor-mcp-common-contract.md#対象の集合)がその場合に各ツールへ委ねる指し方
  として、対象を一つに定める組の並びで受け取る。組は `kind`(対象の種別)・`name`(対象の名前。
  カメラのように種別の中で対象が1つだけのときは持たない)・`path`(同じ対象の中に同じ種別の演算子
  への道が複数あるときの、その道の名前を機械変換したもの。一つに決まるなら持たない)からなる。
  同じテンプレートを全対象へ配る——単数にすると、複数のボーンへの適用が対象の数に比例した
  呼び出しになる。**組が指す対象が無いときは**
  適用できない**とし、その組を説明に
  含める**——指し方は正しく、いまの状態にその対象が無いのだから、指し方の誤りとは分ける。応答は
  **適用した対象の件数 `applied`** とし、件数の上限は
  [要求サイズ予算](pmx-editor-mcp-common-contract.md#要求サイズ予算)から逆算する。
- **`frames`**: そのシグネチャのフレームの引数に従う。単一のフレームを取るものは要素1つ、範囲を
  取るものは開始と終了の要素2つ、フレームの引数を持たないものは `frames` を持たない。**フレームの
  引数は引数の名前で見分け、その名前は `frame`・`start`・`end`・`frameSt`・`frameEd` で閉じる。**
  同じ型の引数を複数取るオーバーロードも、この名前で分かれる。
- **`params`**: 残りの引数を[値の表現](pmx-editor-mcp-common-contract.md#値の表現)で写したもの。
  `frames` へ写した引数はここへ入れない。

**同じ `type` の同名のオーバーロードは、`frames` の有無と要素数、`params` の構成で機械判別できる
ときだけ、同じテンプレートへ集める。** 判別できない組は集めず、違いのある引数の
[表現の綴り](pmx-editor-mcp-common-contract.md#表現の綴り)を後ろに付けた別のテンプレートへ分ける。

## 検査

規則適合検査が、次を検査する。

- 導いた名前が[合成ツール](pmx-editor-mcp-common-contract.md#合成ツール)の名前と**重ならない
  こと**。合成ツールは行を持たないので、重なると1つのツールが行と合成ツールの表の両方から現れる。
- 導いた名前と合成ツールを合わせたものが、[スキーマ正本](pmx-editor-mcp-common-contract.md#スキーマ正本)が
  持つツールと**過不足なく一致すること**。形の無いツールは呼び出しの入出力を誰も決めておらず、
  どちらにも無いツールの形は行き先を失っている。ただし**分岐を持つ合成ツールの形は、イベント行が
  1件以上あるときだけ求める**——その形は分岐をイベント行から得るので、イベント行が無ければ書けない。
- **埋め込み先の名前**が、宣言型の役割に応じた先であること——コネクタ型・操作対象型・ハンドル
  操作型のプロパティは**その型について型役割表から導く取得と更新のツール**、イベント引数型のプロパティは
  **能力対応表が持つイベントの分岐**、DTO型のプロパティは**能力対応表が持つツールの名前かイベントの
  分岐**(関わるツールがどれかは型からは決まらないので、実在することまでを見る)。埋め込み先は
  名前でしか指せないので、綴りの取り違えはここでしか出ない。
- **`type` と `targets` の要素の種別と道、それに引数の判別が、組として一つに定まること**。
  ホストはこの組からSDKの呼び出し先を決めるので、二つに読める組が在るとどちらを呼ぶかが決まらない。
- **`targets` が指せる種別と道の組が、モーションイベントのデータから演算子の型へ至る取得の経路を
  漏れなく覆うこと**。母集団は公開API列挙から決まる。指せない経路の先にある演算子は、
  テンプレートが在っても呼ぶ相手を与えられない。
- [能力対応表](pmx-editor-mcp-common-contract.md#能力対応表)のイベント行が持つ **`eventType` が、
  行の全体で重ならないこと**。同じ識別子が2つの行に付くと、受け取り側はどのイベントが起きたのかを
  決められない。
- 同じツールへ集めた**呼び分けが、入力で相互に判別できること**。判別できない呼び分けを残すと、
  どちらの呼び出しなのかがホストの側で決まらない。**2つの呼び分けを見分けられる**のは、次のどれかが
  成り立つときとする——どちらも分岐を選ぶ項目を持ち**同じ名前で違う値**を選ぶ、片方が必ず渡す項目の
  名前を**もう片方がどの入力にも持たない**、どちらも必ず1つを渡すまとまりを持ちその2つが**共通の
  名前を持たない**。入れ子の中も同じで、両方が同じ名前の組か**空にできない組の配列**を持つなら、
  その中の必ず渡す項目へ同じ規則を当てる——空にできる配列は、空の要求がどちらにも当てはまるので
  見分けに使えない。**形が違うだけでは足りない**——どちらにも当てはまる要求が作れるなら、ホストは
  呼び分けを決められない。
