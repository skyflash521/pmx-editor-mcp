# pmx-editor-mcp ツール仕様書

SDKの公開メンバーを、MCPクライアントへ見せるツールへどう写すかを定める。値の表現・応答の包み・
共通の引数・入出力の形と受け手は[共通契約仕様書](pmx-editor-mcp-common-contract.md)、型の役割と
型ごとのツールの名前は[型役割仕様書](pmx-editor-mcp-type-roles.md)が持つ。

## メンバーから決まるツール名

[型役割表](pmx-editor-mcp-type-roles.md#正本の形)が名前を持つツールは、その名前を正本とする。
ここが定めるのは、それ以外の、メンバーから名前が決まるツールである。

[動作の語](pmx-editor-mcp-common-contract.md#ツールの説明文)は、シグネチャのメンバー名を
PascalCaseからsnake_caseへ**機械変換**したものとする。ただし**公開コンストラクタから作るツール**は、
その動作の語を `create_<型役割表の要素名詞(単数形)>` として機械変換の例外とする——コンストラクタ
には変換元のメンバー名が無いためである。生成を受け持つメソッドはメンバー名を持つので、例外に
当たらない。

**担当群は宣言型から取る。** 作る型から取ると、同じ名前のツールの行が宣言型ごとに分かれ、
[説明文](pmx-editor-mcp-common-contract.md#ツールの説明文)が求める「同じ名前の行の宣言型がすべて
同じであること」と食い違う。

**出所修飾**——型役割表の要素名詞(単数形)——は、型の公開メソッドでは衝突の有無によらず付け、
コネクタ型のメソッドでは同じ担当群の中で**2つ以上のツールに現れる動作の語**を持つときだけ付ける。
同名のオーバーロードは1つのツールへ集まるので、衝突は行の数ではなくツールの数で数える。型の公開メソッドで常に
付けるのは、同じはたらきのメソッドが型をまたいで現れるためである。**動作の語を例外とした生成の
ツールは出所修飾を持たない**——何を作るかは、その動作の語の要素名詞が既に表している。

## メンバーの写し方

- **メソッドは1メソッド=1ツール**とする。メソッドは引数の構成と意味が個別なので、集約すると
  入力のスキーマが分岐の集合になり、検索でツールを引けなくなる。
- **プロパティは1件ずつ写さず、宣言型ごとに集める**。コネクタ型のプロパティは型役割表が持つ取得と
  更新の2つへ、ハンドル操作型と操作対象型のプロパティは同じく型役割表が持つ一覧と更新の2つへ集める。
  プロパティは引数を持たず値の読み書きしかしないので、メソッドと違い集めても入力のスキーマは
  分岐しない。
- **同じツールへ集める同名のオーバーロードは、JSONへ写した入力で相互に機械判別できなければ
  ならない**。判別に使うのは必須の項目の名前の集合・型・配列の要素数で、出力だけに現れる引数は
  含めない。判別できない組(文字列の版とバイト列の版がどちらもJSONの文字列になる場合など)は同じ
  ツールへ集めず、違いのある引数の[表現の綴り](pmx-editor-mcp-common-contract.md#表現の綴り)を
  後ろに付けた別のツールへ分ける。

## 型の役割ごとの写し先

役割の定義と評価の順は[型役割仕様書](pmx-editor-mcp-type-roles.md#役割)が持つ。

- **コネクタ型・操作対象型・ハンドル操作型**: メンバーを上の
  [メンバーの写し方](#メンバーの写し方)どおりに写す。ハンドル操作型の受け手を集合で受け取るのは、
  単数にするとVMDのキーやUIモデルの操作が対象の数に比例した呼び出しになり、操作対象型だけを集合に
  した意味が失われるためである。
- **イベント引数型**: 独立したツールを作らず、読み取れる全プロパティをそのイベントの `payload` の
  スキーマへ埋め込む。
- **DTO型**: 独立したツールを作らず、プロパティを方向ごとに(応答へは読み取れる全項目、入力へは
  書き込める全項目)関わるツールの入出力のスキーマへ埋め込む。

## 検査

規則適合検査が、次を検査する。

- [能力対応表](pmx-editor-mcp-common-contract.md#能力対応表)が持つツールの名前が、**導いた名前と
  一致すること**。メンバーから名前が決まるツールは上の機械変換と出所修飾から、型役割表が名前を持つ
  ツールはその表から導き、公開コンストラクタのツールは上の例外の形から導く。取り違えて割り当てた
  行は、名前の食い違いとしてここに出る。
- **埋め込み先の名前**が、宣言型の役割に応じた先であること——コネクタ型・操作対象型・ハンドル
  操作型のプロパティは**その型の型役割表が持つ取得と更新のツール**、イベント引数型のプロパティは
  **能力対応表が持つイベントの分岐**、DTO型のプロパティは**能力対応表が持つツールの名前かイベントの
  分岐**(関わるツールがどれかは型からは決まらないので、実在することまでを見る)。埋め込み先は
  名前でしか指せないので、綴りの取り違えはここでしか出ない。
- 同じツールへ集めた**呼び分けが、入力で相互に判別できること**。判別できない呼び分けを残すと、
  どちらの呼び出しなのかがホストの側で決まらない。
