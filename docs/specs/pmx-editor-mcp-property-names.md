# pmx-editor-mcp 日本語名仕様書

SDKの公開プロパティ1件ごとに付ける日本語名の正本と、その付け方の規則を定める。名前は
ツールの説明文の索引語と、発見可能性を測る想定質問文が引く語であり、
[`pmx-editor-mcp-property-names.json`](pmx-editor-mcp-property-names.json) がその値の正本である。

型ごとの役割・要素名詞・ツール名は別の表が持つ。この表を型ごとの項目へ入れ子にしないのは、
鍵が違うためである——型ごとの表の鍵は役割対象の型だが、この表の鍵は宣言型で、継いだプロパティの
宣言型は基底型であり、その基底型自身が役割対象とは限らない。入れ子にすると同じ項目が役割対象の
数だけ重複し、下記の「同じ宣言型の同じ名前は1件」と衝突する。

## 対象

**役割対象の型**が持つ**読み取り可能な公開プロパティ**を対象とする。役割対象の型は、能力台帳と
除外一覧とSDKの列挙から機械で導く——本書は値としてそれを持たず、日本語名の照合が同じ3つを引数に
取るのはこのためである。

宣言したプロパティに限らず、基底型から継いだものと、対象アセンブリ外の型が持つものを含む——役割
対象にはイベント引数の外部型が入り、その型の項目も応答へ埋め込むためである。同じ宣言型の同じ名前は
1件として数える。

宣言型・プロパティの型は、名前空間を含む完全名で書く。入れ子は `+` で区切り、総称型は山括弧の中へ
その段の型引数を並べ(複数あればカンマで区切り、空白を入れない)、配列は角括弧、参照渡しは末尾の
`&` で表す。同じ総称型でも開いた定義と閉じた型は別の項目になる——プロパティの型が違い、応答の形も
違うためである。

## 記載の取り出し

配布物のドキュメントXMLからその member の**記載**を取り出す操作を、次の一つの手順で定める。名前を
採るのも、決め方を分けるために数えるのも同じ文字列を見るので、別々に定めると食い違う。

1. その member の `summary` を取る。
2. 行ごとに前後の空白を落とし、空行を捨てる。
3. **最初の行だけ**を採る。
4. その行に縦棒があれば**最初の縦棒より前**を採り、その末尾の空白を落とす。
5. 空白で区切った**末尾の1トークン**が `get`・`set`・`get/set` のいずれかに一致したら、そのトークンと
   その直前の空白を除く。一致しなければ何も除かない。

残った文字列がその member の記載である。空になる member は記載を取り出せなかったものとして扱う。

最初の行だけを採るのと、縦棒より前だけを採るのは、どちらも同じことをしている——配布物のXMLは名前に
続けて値の意味の補足を書く箇所を改行と縦棒の両方で作るので、補足を落とさないと名前にならず、接尾辞も
末尾に来ないので除去が効かない。末尾を1トークンとして見るのは、末尾の文字列だけを見て除くと
`get/set` から `set` だけが落ちて `get/` が残り、除いた後の空白も残るためである。

## 名前の決め方

各項目は日本語名と、その名前をどう決めたかを必須で持つ。決め方は次の2つだけとする。

- `quoted`(記載を採る): その型の中で他の項目と重ならない記載がある項目。名前はその記載をそのまま
  採る。記載の位置である member 名は、宣言型とメンバー名から一意に導けるので書き写さない。
- `authored`(名前を起こす): **使える記載が無い項目**——記載自体が無いものと、記載はあるが同じ型の
  別項目と同じ名前になるものの両方を含む。**意味の根拠**と、名前の由来の一文を持つ。根拠は次の
  どちらかとする。
  - `documentSection`: 配布物の資料が意味を説明している場合。配布物からの相対パスと、開始行・終了行
    (どちらも1から数え、両端を含む)を持つ。綴りで探す形にしないのは、同じ綴りが資料の別の箇所にも
    現れる項目と、資料に一度も現れない項目の両方があるためで、綴りの出現では位置が一意にならない。
  - `memberShape`: 資料が意味を説明していない場合。宣言型・メンバー名・プロパティの型に拠る。この3つは
    項目自身の鍵なので、下の一対一の照合が同じことを課す。値としては持たせない。対象アセンブリ外の型の
    項目はこれを使う。実行環境の外部文書へは依存しない——版と言語が固定できず、配布物の中で解決できない
    ためである。

**決め方は書き手が選べない。** 上の手順で取り出した記載を同一の宣言型の中で数え、その数が1のときだけ
`quoted` を認め、0または2以上のときは `authored` を要求する。数える母集合は対象の項目のうち記載が
取れたものに限り、同じ宣言型にあっても対象外の member の記載は数に入れない。これを課さないと、一意な
記載がある項目を勝手に `authored` にしたり、同じ記載を持つ項目群の1件だけを `quoted` に残して残りへ
別の名前を付けたりできてしまい、名前が重ならないので下の重複の検査にも掛からない。

## 検査

日本語名の照合が、次を検査する。

- 項目の集合が、列挙で得た宣言型・メンバー名・プロパティの型の組と**一対一で一致すること**。これが
  無いと、公開プロパティを丸ごと書き落としても、同じプロパティを別の名前で二重に載せても、残った
  項目だけが条件を満たして通ってしまう。3つ目に型を入れるのは、型を検査するのが `memberShape` の
  根拠だけだと、`quoted` と `documentSection` の項目で型を取り違えても通ってしまうためである。
- 決め方が、上記のとおり記載の出現数から決まる側と一致すること。
- `quoted` の名前が、導いた member 名の記載と一致すること。
- `authored` の `documentSection` で、相対パスの資料が実在し、終了行がその資料の行数に収まること。
- 同一の宣言型の中で日本語名が重複しないこと。

次の条件は正本を読む時点で確かめる。日本語名が空でないこと。決め方が上記2つのいずれかであること。
`authored` の根拠の種別が上記2つのいずれかであること。`authored` の由来の一文が空でないこと。
`documentSection` の開始行が1以上で、終了行が開始行を下回らないこと。そして、項目が宣言型・メンバー名の
序数の昇順に並び、同じ宣言型の同じメンバー名が二度現れないこと——並びを列挙側と同じ定義にそろえるので、
項目を足すときは末尾ではなくその位置へ入れる。

**機械で確かめられるのはここまでである。** 起こした名前が的確かどうかを測る検査は置かない——想定
質問文の検査は質問文へこの日本語名を埋めて引くので、名前が不適切でも文字列が一致すれば通り、名前の
良否を測る検査にならない。`authored` の名前は書き手の判断で決め、その判断を由来の一文と根拠が後から
追える形にする、というところまでを規則とする。
