# エディタを起こす

いまのHEADのブリッジとホストでMCPのツールを呼べる状態にし、エディタを起こすまでの手順。

## 手順

1. ホストを配置する。`pwsh -File scripts/deploy-host.ps1`
2. ブリッジを発行し、その写しをMCPサーバーへ登録する。
   **発行先は固定の親の下へ世代ごとに作る**——`$env:LOCALAPPDATA/pmx-editor-mcp-dev-bridge/<世代>`。
   **配布物の導入先(`$env:LOCALAPPDATA/pmx-editor-mcp`)の下へ置かない**——同梱の手順の
   アンインストールはそのフォルダごと消すので、開発中の世代まで巻き込む。
   **環境変数はこの段で使うシェルが展開する形で
   書く**——`%…%` はここでは展開されず、その名前のディレクトリが作業ツリーへ残る。
   `pwsh -File scripts/publish-bridge.ps1 -Destination <発行先>` で出し、
   `claude mcp add -s user pmx-editor-mcp -- "<発行先>/PmxEditorMcp.Bridge.exe"` で登録する。
   **ビルド出力を登録しない**——セッションがそれを掴み、後のビルドが上書きできずに落ちる。
   **ユーザースコープで登録する**——プロジェクトごとの登録はドライブ文字の大小で割れる。
   **写しがいまのビルド出力より古いとき、または登録が固定の親の下を指していないときに、前と違う
   発行先へ出して登録を入れ替える。**
   同じ発行先へ出し直すと、その写しを掴んでいるセッションがあるかぎり発行の側が落ちる——
   ビルド出力のロックが発行先へ移るだけである。入れ替えるときは `claude mcp remove pmx-editor-mcp`
   を先に通す——同じ名前が残っていると登録が拒まれる。
   どちらにも当たらないなら発行も入れ替えも要らない。
3. 手順2で登録を変えたなら、セッションを開き直す。ツール定義は開始時にしか読まれない。
4. `$env:LOCALAPPDATA/pmx-editor-mcp-dev-bridge/` の下で、掴まれていない世代を消す。開き直した先が
   掴むのは登録した1つだけなので、ここでなら前の世代もまとめて消せる。**2で消そうとしない**——その時点では
   自分が掴んでいる。
5. エディタを起こす。`pwsh -File scripts/host-control.ps1 -Action launch`
6. `ping` が `pong` を返すことを確かめる。
