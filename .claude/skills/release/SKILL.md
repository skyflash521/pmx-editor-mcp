# リリース

手順の正本は [リリース手順](../../../docs/conventions/release.md)。

## 確認を取る場面

次の場面では、案を示してユーザーの確認を受けてから進める。修正を受けたら反映して示し直す。

| 場面 | 示すもの |
|---|---|
| バージョンの決定 | 指定が無ければ、[バージョン付け](../../../docs/conventions/versioning.md)に従った案と、どの変更がどの桁に当たるか |
| 変更履歴の節 | 起草した節と、採ったコミット・落としたコミットの対応 |
| PR案 | [PR案のひな形](#pr案のひな形)に沿ったタイトルと本文。確定をもって develop の push と PR の作成の了承とする |
| アカウント | `gh auth status` のホストとユーザー名 |

確定を受ける文面はチャットの本文に書き、転記する文面はコードブロックで示す。AskUserQuestion の
選択肢へは載せない。

## 始める前

- 作業ツリーとブランチを確かめる。コミットしていない変更があるか、develop でないときは、その状態を
  示して確認を受ける。stash・破棄・ブランチの切り替えを勝手に行わない。
- gh を使い始める前に、[アカウント](#確認を取る場面)の確認を受ける。gh のコマンドには
  `--repo skyflash521/pmx-editor-mcp` を付ける。

## 変更履歴を起草する

手順書の[変更履歴を書く](../../../docs/conventions/release.md#2-変更履歴を書く)の規準で起草する。

1. **前のバージョン**: 最新の `v*` タグを取る。`CHANGELOG.md` の先頭の節と同じバージョンでなければ、
   進めずに確認を受ける。
2. **材料**: `git log v<前のバージョン>..develop` のコミットと、`git diff --stat v<前のバージョン>..develop`
   の差を並べる。
3. **取りこぼしの確認**: 次の差がすべて材料に現れていることを確かめる。
   - ブリッジが `tools/list` で返すツール名と引数。前の Release の zip のブリッジと、今回組み立てた
     ブリッジを [mcp-client.mjs](../../../scripts/mcp-client.mjs) で起こして並べ、突き合わせる。
     突き合わせるスクリプトは `.scratch/` に書き、終わったら消す。
   - `docs/package/INSTALL.md` と、[製品の要求](../../../docs/conventions/requirements.md)が定める
     PMXエディタの下限の、前のタグとの差。
4. **仕分け**: エンドユーザーから見える変更だけを採り、区分へ割り当てて起草する。
5. **提示**: [確認を取る場面](#確認を取る場面)のとおり示し、確定した節を `CHANGELOG.md` の先頭へ足す。

初回は 1〜3 を行わない。

## 公開前の検証

手順書の[公開前の検証](../../../docs/conventions/release.md#3-公開前の検証)を走らせる。通らない項目が
1つでもあれば、PR へ進まずに結果を報告する。

## コミット

バージョンの書き換えと変更履歴の節を、1つのコミットにまとめる。

## PR案のひな形

- タイトル: `release: v<バージョン>`
- 本文:

  ```markdown
  ## 変更点

  (CHANGELOG.md の該当バージョンの節の本文をそのまま写す)

  ## 検証

  - verify.ps1 -All: <結果>
  - verify-live.ps1 -All: <結果>
  - 配布パッケージから導入した状態の検査: <結果>
  ```

PR案が確定したら、develop を push し、develop から main への PR を `gh pr create` で作る。
`gh pr checks <番号> --watch` で PR の検査の結末を待ち、合格したことを報告する。不合格なら原因を
報告して止まる。

## PR を作った後

指示を受けた段だけを実行し、各段の結果を報告して次の指示を待つ。

1. **マージ**: `gh pr merge <番号> --merge` でマージコミットを作る。
2. **タグ**: 手順書の[タグを打つ](../../../docs/conventions/release.md#5-タグを打つ)のコマンドで、
   マージコミットへタグを打って push する。
3. **Release**: 手順書の[Release を作る](../../../docs/conventions/release.md#6-release-を作る)を、
   タグのコミットを `git worktree add --detach` で一時フォルダへ取り出して行う。走らせた後に
   `gh release view v<バージョン>` で、タイトル・本文・添えた zip が変更履歴の節と組み立てた
   パッケージに合うことを確かめ、作業ツリーを `git worktree remove` で片付ける。

どの段で失敗しても巻き戻さず、実行した範囲と失敗の出力を報告する。
